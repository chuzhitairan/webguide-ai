## E01 首次加载与页面检查

来源：用户粘贴的扩展诊断文本；只移除粘贴格式转义并整理排版，保存为[首次加载记录](evidence/2026-11-17/first-load.json)。没有新增截图或独立浏览器复现。记录时段为北京时间 2026-11-17 15:54:05.727–15:55:01.111，原始 JSON 保留 UTC 时间。

- UA 报告 Edge 157；sidePanel、onOpened、onClosed、storageSession 的能力标志均为 true。能力存在不等于相应事件已实际触发。
- 同一 bootId 下有页面连接、侧栏连接、任务开始、检查发出与观察接纳；settings 角色命中 `unique-visible`，documentId 和 taskId 已记录。
- 检查后约 10 秒收到高亮撤销通知，原因为 `10-second-test-lease-expired`。这支持租期到期的撤销路径；没有用户视觉反馈，不能单凭此记录认定蓝框显示位置和视觉效果通过。
- 任务仍为 active，与“只撤销过期高亮、保留任务及历史观察”的实验行为一致，不表示发布成功。
- 本段没有 native-panel-opened／closed 或 panel-disconnected 事件；关闭检测、暂停继续、跨页／跨源和后台重启仍待后续实测。下一项先在租期内关闭侧栏，观察蓝框撤销，并核对重新连接前是否已有暂停记录。

## E02 关闭侧栏与重新打开

来源：用户粘贴的[关闭侧栏诊断记录](evidence/2026-11-17/close-panel.json)，格式整理方式同 E01；用户另明确反馈“蓝框是在关闭侧栏同时消失的”。本次用户清空并开始了新任务，与 E01 的任务不同，记录分别保存。

- 北京时间 16:01:31.344 接纳第二次 settings 检查；16:01:32.612 收到原侧栏实例的 `panel-disconnected`，同一时刻记录 `task-paused / panel-connection-lost`，相隔 1.268 秒，早于 10 秒租期。
- 16:01:42.339 新侧栏实例连接；任务保持原 taskId、paused、owner=null，revision 从检查时的 2 增至 3。暂停发生在重新连接之前，没有因打开面板自动恢复。
- 结合用户视觉反馈，本机 Edge 157 上本次单窗口关闭路径通过：连接断开后暂停并撤销当前蓝框，重开保持暂停。没有据此认定所有页面均已确认停止。
- 此段未出现 `native-panel-closed`，不能宣称原生 onClosed 回调已触发，也不据缺失日志认定该 API 不可用。连接断开继续作为保守停止信号，不等同于唯一关闭原因。
- 当前 bootId 与 E01 不同，但中间有 reset 且未保留重启前后连续记录，不能把两段 bootId 差异当作后台恢复验证通过。
- 下一项：继续同一任务，在模拟工作流页及第二端口新标签页分别核对，检查 taskId、页面角色和文档关联。多窗口、旧实例迟到断开与后台恢复另测。

## E03 同源换页与跨源新标签

来源：用户附件 `Pasted text.txt`，按原文件内容复制为[跨页诊断记录](evidence/2026-11-17/cross-page.json)，未改写字段；用户确认工作流页和站点页“都有蓝框”。记录时段为北京时间 2026-11-17 17:06:21.647–17:07:08.657。

- 本次先 reset 并创建新任务；与 E02 的 taskId 不同。E03 内部从开始、关闭暂停、重开后继续到三页核对，全程同一个 taskId `7bb3ac42-e254-4eff-9994-ce0dbe284029`，没有以跨 E02 保持同一任务为结论。
- 最终 settings、workflow、site 三项观察均为 `unique-visible` 且 taskId 一致。settings／workflow 使用同一 tabId、不同 documentId，支持同源整页换页后重新连接和核对；不是 SPA 验证。
- site 使用另一个 tabId 和 `127.0.0.1:43118`，与前两页 `:43117` 不同 origin；支持本机第二端口新标签页关联原任务。没有据此认定真实 GitHub → github.io 的主机授权已通过。
- 用户确认工作流与站点均看到蓝框，补充了视觉显示证据；没有定量测量定位精度。记录中的 `document-hidden` 撤销发生在相应检查后数秒内，支持页面隐藏时的撤销路径，但仍不替代所有导航／目标失效情形。
- 同一 bootId 内先有连接中断暂停，随后新面板连接并接纳修订 3 的 settings 检查，最终为 active 且 owner 为新面板实例，支持本段的显式继续路径；没有后台重启事件，也未验证多窗口隔离。
- 结论：本次本机同源换页、第二端口跨源新标签关联及两页蓝框显示通过。下一项检查目标移除／重建与无刷新 URL 变化，随后检查后台恢复和多窗口。

## E04 DOM 与地址变化

来源：用户粘贴的[失效诊断记录](evidence/2026-11-17/invalidation.json)，移除粘贴格式转义、保留字段值。北京时间 17:12:11.358–17:12:42.746；本次 reset 后另建任务，单独记录。

- 记录含两次 `dom-changed-recheck-required` 撤销，其间重新核对可接纳 `unique-visible`。支持 DOM 变化撤销与后续重新定位的程序路径；未记录具体按钮动作或本轮视觉反馈，不把两次 DOM 变化分别断言为已完整验证的移除／重建操作。
- 最后一次有效检查后，同一 documentId 的页面有 `tab-navigation / allowed=false`、DOM 变化撤销，再次核对得到 `check-unavailable`；任务原因更新为 `outside-fixture-or-page-not-ready`。支持本机无刷新地址变化后的拒绝核对路径。
- 最终保留的 site 观察时间早于地址变化，是历史观察，没有新的接纳事件或完成结论。此轮也有 `document-hidden` 撤销记录，不能将所有撤销都归因为移除目标。
