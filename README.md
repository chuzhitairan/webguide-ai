# WebGuide AI

WebGuide AI 帮助用户在真实网页中理解并完成操作，并支持作者获取、编辑、验证和维护可复用教程。用户按页面内指示自行操作，系统核对步骤与结果，AI 结合上下文解释答疑。

## 过程模型与交付

采用增量迭代：围绕一个可执行用户闭环，依次计划、构造、测试、评审，再形成可交付版本。前期用小型可行性实验解决高风险问题；后续需求、模型、代码和验收通过 Issue 与 PR 关联。课程文档检查按课程时间表完成，工程工作可在输入足够时继续，不用文档数量代替产品结果。

选择原因：网页动态变化和模型不确定性需要早期反馈；完整系统覆盖作者与学习者，分期实现能降低首次集成风险。单次整体交付发现问题较晚；纯原型又难以保留版本、评审与验收证据，因此采用有明确交付与回顾的增量过程。

课程资料列有至少 3 个增量、2 轮迭代等建议与检查项，原文保留在课程时间表；项目按实际闭环与反馈安排迭代，具体课堂提交方式由组长与教师沟通。Pages 保留为已有技术验证与后续教程候选。文档基线与软件版本分别命名。

## 风险清单

| 风险 | 影响 | 应对与当前证据 |
| --- | --- | --- |
| 页面改版、SPA 导航或目标重建 | 高亮失效、指错位置 | 撤销失效指示、唯一性核对、定位重试；已有局部实验，真实站点持续集成仍待验证 |
| 中间成功误报最终成功 | 发布错版本、遗漏步骤 | 区分动作与结果，关联配置／部署／内容；已有 Pages 正反例记录 |
| AI 错误解释或网页指令干扰 | 误导用户、越界建议 | AI 与规则分离、最小证据、回答绑定当前上下文；集成验收待实现 |
| 范围过大与团队参与不均 | 主线拖延、成员讲不清工作 | 组长与助手先收尾文档；后续按需要安排有限工作包、集中评审与试用，贡献据实记录 |
| 需求证据或课程过程缺失 | 需求偏差、检查材料不齐 | 区分公开讨论与独立访谈；原型后补试用，教师反馈与真实 Review 另行跟踪 |
| 第三方组件耦合与许可 | 集成成本、复用受限 | 参考固定版本源码；具体依赖核对许可和适配成本再引入 |
