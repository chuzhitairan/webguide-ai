# WebGuide AI：实现难度与复用方案

评估日期：2026-11-13。根据本地下载的九个项目及其核心路径静态阅读结果估算；上游组件尚未在本机安装和运行。功能相似是可利用的工程基础，本方案以主动复用为前提。

## 1. 总体判断

**针对选定网站的课程完整版本，难度约 6/10，属于中等偏上、范围可控的项目。**它可以同时包含录制、AI 生成、高亮、进度监测、有限场景纠偏和教程管理。主动复用使这些功能可以保留，无须为了回避重合而删掉。

**原提案若被理解为任意网站都能自动学会、各种改版都能恢复、无需人工校验就能批量发布教程，难度约 9/10。**两档的主要区别是适配范围、自动验证程度和可靠性要求。分数是本次工程判断，不是测量结果。

下面的工期以三人小组为例：已有基础 Web 开发经验，每人每周投入约 10 小时有效开发时间，合计 30 小时；会使用 AI 编程辅助；模型 API 和演示账号可用。有效开发时间包含必要阅读、调试、测试和文档，不等同于坐在电脑前的时长。

## 2. 功能与复用后的难度

| 功能 | 难度 | 优先复用/借鉴 | 本项目仍要完成的工作 |
| --- | --- | --- | --- |
| 页面高亮、气泡、步骤按钮 | 低 | Driver.js | 注入插件、打包 CSS、层级与滚动处理、动态目标更新 |
| 教程列表、编辑、发布和基础统计 | 低至中 | OnTheWay；参考 Usertour 模块 | 接上统一教程格式、版本和插件接口 |
| 录制点击与输入并整理步骤 | 中 | OnTheWay 录制器；参考 rrweb/OpenAdapt 的证据结构 | 目标语义、输入合并、跨页记录、过滤录制器自身操作、敏感字段处理 |
| 文档/录制记录生成教程草稿 | 中 | OnTheWay 的生成接口和结构化输出思路 | 文档清洗、字段校验、将文字步骤对应到实际页面目标、编辑确认 |
| 插件侧边栏、通信和跨页恢复 | 中 | Nanobrowser 的扩展结构；OnTheWay 的恢复思路 | 标签页与教程状态隔离、刷新/导航/服务进程重启后的恢复 |
| 根据页面状态判断步骤完成 | 中至高 | Usertour 的 watcher 与规则评估 | 为步骤定义可检查条件；区分已点击、页面已变化、任务已完成 |
| 指定场景中的 AI 纠偏 | 中至高 | Nanobrowser 的页面表示；OpenAdapt 的修复流程 | 检测偏离、定位候选、判断可否恢复、恢复后重新验证 |
| 固定网站、固定任务的沙盒自主探索 | 中至高 | 选择一个 Browser Use 或 OpenAdapt 执行方案验证 | 准备账号/初始状态、记录轨迹、任务成功检查、清理测试数据、转教程 |
| 任意第三方网站、复杂控件和大幅改版适配 | 很高 | 现有 Agent/定位实现只能覆盖一部分 | iframe、Shadow DOM、权限分支、多标签页、流程变化、持续回归 |

这里的“复用”有三种形式：直接引入库、在许可允许下修改已有模块、借鉴数据结构和控制流程。Driver.js 最适合先作为直接依赖；OnTheWay 的录制/引导模块适合改造；Nanobrowser/OpenAdapt 的整体系统较重，先借鉴关键机制。整套克隆和拼装也有学习、依赖和接口适配成本。

## 3. 三种交付范围和工期

| 交付范围 | 内容 | 总有效工时估计 | 三人、合计 30 小时/周 |
| --- | --- | --- | --- |
| 首个可演示闭环 | 单站点、1～2 个任务、简易录制/编辑、页面引导、基础条件检查、一类 AI 恢复 | 60～120 人时 | 约 2～4 周 |
| 建议的课程完整版本 | 1～2 个选定站点、3～5 个任务、录制、文档生成草稿、插件引导、有限纠偏、版本和基础统计、测试与文档 | 180～300 人时 | 约 6～10 周 |
| 在上述版本上加入自主探索试验 | 单一沙盒任务；使用现成 Agent 执行并记录，成功后转为可编辑教程 | 额外 40～80 人时 | 额外约 1.5～3 周，可由独立模块负责人提前并行验证 |

区间包含初步阅读、适配、联调和修复预算，尚未经最小原型校准。模块并行有帮助，但插件与后端必须先约定教程格式，之后仍需共同联调。若团队不熟悉 TypeScript/扩展开发，或可用时间明显不足，应取上界并预留学习时间。人员增加不意味着工期能完全按人数线性缩短。

原提案的通用化版本不适合在未做原型前给出固定课程工期。应先测量跨站定位与纠偏失败率，再决定支持范围。

## 4. 最值得采用的开发路线

### 先打通使用流程

用 Driver.js 在实际插件中加载一个手写教程：打开页面、找到目标、高亮、用户点击、检测下一状态、跨页后恢复。这个原型同时验证插件环境、渲染、定位和状态通信，比先做完整广场更能校准总难度。

### 加入作者录制与编辑

优先改造 OnTheWay 的录制与步骤编辑思路。录制输出统一格式，教程作者可以补充完成条件和说明，再发布一个固定版本。保留它已有的好用功能，包括点击推进、等待、跨页恢复，无需自行重新实现相同机制。

### 加入 AI 生成与有限纠偏

文档输入和操作录制都先产生草稿。纠偏先支持几个具体场景：用户走入错误菜单、关闭必要弹窗、目标文案或布局变化。发送当前页面过滤后的候选结构，模型返回候选目标或恢复步骤，插件再次解析并验证。

接入模型返回 JSON 的工作量通常有限，主要调试会发生在什么时候触发、页面状态是否读全、候选是否选对，以及恢复后教程是否能继续。不要把每次点击都交给模型判断；可以借鉴现有项目，正常流程使用本地规则，异常再请求 AI。

### 自主探索作为一个可独立验证的功能

保留这个方向。在指定沙盒中选一个任务，例如创建项目，复用现成浏览器 Agent 执行，保存动作前后状态，并判断最终任务是否成功。成功轨迹转成教程草稿后再检查和发布。

“能在固定沙盒生成一份有效教程”已经可以体现这项功能。扩展到各类网站和账号，需要任务初始化、环境重置、不同权限和错误路径处理，工作量会继续增加。Agent 使用的后端浏览器与用户当前浏览器也要区分：前者适合沙盒探索；实际用户纠偏应基于用户当前页面。

## 5. 复用时需要尽早验证的具体问题

1. **版本一致。** 本次 OnTheWay 代码包含 Driver.js 1.3.1 的 CSS CDN 地址，而下载的 Driver.js 是更新的源码。先选择固定版本，将 JS 和 CSS 一起打包；不要默认新旧文件能直接混用。
2. **运行位置。** 侧边栏中的界面和网页中的高亮在不同上下文，必须通过明确的消息传递。把普通网页 SDK 接入扩展需要改造。
3. **页面状态持久化。** OnTheWay 使用 sessionStorage；插件需要考虑 tab、origin 和教程版本。复用跨页恢复思路后仍需处理多标签页和跨域。
4. **教程完成判据。** 可以复用 watcher 和条件评估，但每个任务的完成条件仍要定义。后端提交失败时，教程不能因为点击发生而进入完成状态。
5. **模型回复与页面时效。** AI 返回期间用户可能继续点击或切换页面，应用回复前要确认仍是同一任务和相容的页面状态，过期回复应丢弃或重新观察。

这些属于集成工作的主要来源，也是总工时中需要保留调试预算的原因。具体源码入口见 [源码阅读索引](./源码阅读索引.md)。

## 6. 课程设计中的工作如何体现

已有组件可以支撑更多功能和更完整的演示。项目仍需自己完成需求与数据建模、插件和服务接口、教程协议、状态管理、AI 调用流程、异常处理、版本记录、部署、场景测试及课程文档。

可以在报告中清楚记录直接使用的库、修改过的模块和自行完成的部分。评价重点放在需求覆盖、系统可运行、测试结果和设计依据。第一版不需要训练模型，也不需要先建设复杂 RAG 系统；教程较少时，可先按站点和任务信息筛选，再接语义检索。

最值得尽快验证的三个环节是：真实插件中高亮和导航是否稳定；录制结果能否重新引导另一个用户完成同一任务；用户故意偏离后 AI 能否恢复且通过完成条件检查。三项原型的结果能进一步收窄上述工期区间。
