# WebGuide AI：Pages 首版需求规格工作稿 v0.1

日期：2026-11-16。状态：T01 整理稿，用于总体架构设计与后续细化。首版范围已确认，技术方案与候选性能参数在设计中落定。

2026-11-17 文档定位澄清：本稿描述 Pages 场景的首版补充规格，不代替[完整系统 SRS v0.2](WebGuideAI-SRS-v0.2.md)。交付分期见[版本交付范围](版本交付范围-2026-11-17.md)；本稿保留原文件名及 Pages 专有需求细节供引用，整体规格不再以本稿单独代表。

## 1. 目的与依据

帮助不熟悉 GitHub Pages 的用户，在真实网页上跟随可视指引发布简单静态页面，并判断预期内容是否已经发布。AI 解释当前步骤和页面证据，结构化规则判断结果，用户执行网站操作。

本稿汇总[已确认范围与决定 D05–D08](第一阶段需求评审与交付范围-2026-11-16.md)、[验收条件 B01–B12](Pages首版验收清单-2026-11-16.md)及[原需求草案](WebGuideAI-需求草案-v0.1.md)，沿用 FR、NFR 和 B 编号。详细流程采用 SC01-A/B/C，作为原 Pages 场景 SC01 的细化，不重编号原有 UC01–UC20。

## 2. 产品范围与参与者

### 2.1 首版范围

- 桌面 Edge、英文 GitHub 页面作为首轮支持基线，指引与答疑使用中文；页面翻译及其他语言组合单独验证。
- 用户已登录，已准备符合发布条件的仓库、分支及简单静态首页；执行 Pages 分支发布，不承担注册账号、编写首页或复杂构建教学。
- 用户可指定符合条件的仓库、分支、目录和预期内容，不限于当前实验仓库。
- 提供页面内目标指示与高亮、规则验证、当前步骤 AI 答疑、同一浏览器会话内暂停继续及最简反馈。
- 覆盖首次发布、已有结果核对和阻塞／偏离处理。权限或前提无法满足时仍应提供可理解的说明与退出路径。

### 2.2 后续范围

教程创建、专家录制、文档生成、编辑发布与维护保留为后续增量；PR、Figma、自定义域名、复杂构建及跨设备恢复随后考虑。原 FR11–FR17、FR19–FR20 的完整能力继续保留在原草案中。首版仅需要一份可维护的 Pages 教程，不据此承诺作者平台已交付。

### 2.3 角色与职责

| 参与者 | 本版职责与边界 |
| --- | --- |
| 学习者／操作用户 | 确认目标、跟随指引、自行选择和保存设置、查看结果、求助、暂停及反馈 |
| WebGuide AI | 展示当前步骤、定位目标、观察必要页面信息、检查规则、解释证据和记录会话 |
| GitHub 与发布站点 | 提供页面、配置和部署过程，是系统观察的外部对象；其响应和权限不由本产品保证 |
| 模型服务 | 根据允许的上下文提供解释与建议；不决定系统验证状态，不执行网站保存、提交或发布 |
| 教程作者／维护者与平台管理员 | 完整产品角色，后续具备各自权限；本版由项目维护者准备教程，不能视为已实现作者／管理平台 |

## 3. 术语与关键约定

| 术语 | 含义与约定 |
| --- | --- |
| 任务目标 | 本次仓库、发布分支、目录、预期版本与内容。站点地址可在发布过程中确认；版本和内容的绑定方式见 Q02 |
| 教程与任务参数 | 教程表达操作目的、步骤与检查；仓库等是某次任务参数。不能把实验仓库作为产品唯一目标 |
| 已保存配置 | 有足够页面证据支持目标发布配置已保存；当前选择值、点击记录或 Save 灰显均不能单独证明已发布 |
| 关联部署 | 与当前目标和本次配置／目标版本对应的部署记录；其他 run 的成功不能替代它 |
| 有效观察 | 属于正确任务与页面对象，来源、采集时间和当前有效性可核对；过期、对象变化或读取失败后不能沿用旧成功 |
| 系统已验证 | 配置、关联部署的目标提交、站点预期内容均有有效证据且关联充分；展示依据与观察时间 |
| 用户确认／待确认 | 用户补充判断与系统验证分别标明；无法取得关键证据时保持待确认。关键结果仅由用户确认时不能显示为系统已验证 |

任务进度至少区分待开始、引导中、等待、受阻、暂停、待确认和结束；结果另标系统验证或用户确认。正式状态字段与转移规则在 T03 定义。

新手不必先知道提交 SHA 才能开始任务。系统应帮助确认本次目标版本；尚未绑定时可以引导已有操作，最终系统验证必须等待关联证据充分。用户切换目标时，应明确形成新目标，不能把原仓库的证据自动迁移。

目标版本需要可核对的来源和确认时刻，绑定后不能随分支的新提交静默改变。Q02 应设计系统辅助确定目标的路径，例如读取已确认目标分支在某一时刻的提交，供用户用可理解的说明确认；不能无提示地把待核验工作流自身的提交当作用户预期。核对指定部署与核对源分支最近修改是否上线的意图需区分。读取失败或目标不明确时给出具体补充／重查路径，不能只有无期限等待。

## 5. 详细用例

### SC01-A：首次发布简单 Pages 页面

**主要参与者**：学习者。**触发**：用户选择发布任务并指定仓库。

**前置条件**：已登录；目标仓库已有可发布的分支与静态首页；本次采用分支发布。配置权限在开始时核对，缺失或未知转入 SC01-C。

**正常流程**：

1. 系统展示目标仓库、分支、目录、预期内容与教程适用条件，帮助用户确认目标版本并记录来源和确认时刻；按 Q02 定义方式绑定，不能要求新手自行提供 SHA 才可开始。
2. 引导用户进入当前仓库 Pages 设置，核对发布源状态；未配置时定位对应发布方式、分支和目录控件。
3. 用户依次选择并保存。系统区分当前表单与已保存状态；有足够保存证据后继续，未保存或未知时保持当前检查。
4. 系统引导打开本次关联工作流；排队／运行时说明等待原因及复查方式，允许暂停，不反复要求保存。
5. 关联工作流成功后核对目标提交；若关联充分，引导访问发布站点并检查预期内容。
6. 规则联合核对配置、部署与内容。全部充分时报告系统已验证，显示依据与观察时间；否则说明还缺哪项。

**成功后置条件**：本次目标有可核对的三类关联证据，结果明确为系统已验证。**其他结束条件**：用户退出，或阻塞／证据不足保留为受阻／待确认；不自动改动网站以凑齐结果。

| 分支 | 处理与返回位置 |
| --- | --- |
| A1 已配置 | 核对是否与本次目标一致，转 SC01-B，避免重复保存 |
| A2 选择与准备的首页位置不符 | 指出差异并由用户决定修正；未知则等待确认，不任意选择分支或目录 |
| A3 保存证据不足、读取失败 | 显示待确认，重新核对步骤 3；本次读取失败不能由先前成功观察补足 |
| A4 部署失败／取消或关联不明 | 转 SC01-C；不得取另一次成功 run 替代 |
| A5 站点尚不可用或内容不符 | 说明本次观察，核对部署与目标版本；保持未验证，按实际情况等待或转 SC01-C |
| A6 任务期间源分支出现新提交 | 保留已确认的目标版本并说明变化；用户明确重设目标时记录变更并重新核对，不自动把较新的成功部署当作原目标成功 |

### SC01-B：核对已有发布结果

**主要参与者**：学习者。**触发**：用户希望确认已有站点，或从 SC01-A 发现已配置后进入。

**前置条件**：已确认目标仓库及预期内容，发布配置可访问；权限或可观察性不满足转 SC01-C。仅有站点 URL 时先补齐目标信息。

**正常流程**：

1. 展示目标和教程，帮助确认预期版本与内容，区分“指定部署”与“源分支最近修改”的意图；记录目标来源和确认时刻，核对现有发布源与本次分支／目录要求。
2. 从当前设置／部署信息定位关联工作流，核对是否为目标部署与目标提交，不复用固定旧链接。
3. 运行中则等待，失败转 SC01-C；成功时定位站点入口，引导用户访问。
4. 检查目标站点的预期内容，并核对此前观察仍有效且属于同一任务。
5. 关联充分则报告系统已验证；若只知道“站点能打开”，指出缺少的配置、提交、部署或内容证据。

**成功后置条件**：已有站点的本次目标得到系统验证，过程无需重复修改配置。**其他结束条件**：待确认、受阻、暂停或用户退出，保留已取得证据及其有效性说明。

| 分支 | 处理与返回位置 |
| --- | --- |
| B1 页面提示已上线，但工作流信息未核对 | 继续步骤 2，不把上线提示作为全部结果 |
| B2 内容可能来自旧版本，或目标发生变化 | 核对版本与预期内容；无法绑定则待确认，不沿用旧任务成功 |
| B3 观察过期或页面已改变 | 重新采集受影响的证据，返回对应检查步骤，不要求重复所有网站操作 |
| B4 用户补充截图或口头确认 | 记录为用户提供的信息／确认并标明来源；不足以系统验证时保持结果等级清楚 |
| B5 目标尚未确定或分支在任务中更新 | 给出明确的目标确认／重查路径；已绑定时维持原目标，变更需明确记录并重新核对 |

### SC01-C：处理阻塞、偏离与恢复

**主要参与者**：学习者。**触发**：系统无法继续验证，用户走偏或主动求助。**前置条件**：已有当前任务，或已识别任务前提不满足。

**正常流程**：

1. 系统暂停当前步骤的错误推进，保留目标和相关有效观察，说明看到了什么、缺少什么。
2. 按下表识别当前可确认的情况；依据不足时标为未知，不以模型猜测代替证据。
3. 给出与当前情况相符的返回、等待、重新授权／核对、查看错误或退出指引；只有目标明确时定位高亮。
4. 用户执行选择，或暂停／退出；求助时模型结合当前证据解释，不自行操作网页。
5. 重新进入已知页面后核对仓库、目标与证据有效性，通过后返回 SC01-A/B 对应步骤；不能恢复则继续受阻或待确认。

**恢复后置条件**：回到可确认的任务上下文，结果由重新核对决定。**其他结束条件**：用户暂停／退出或外部阻塞仍存在；保持实际状态，不显示虚假完成。

| 情况 | 必须给出的行为 |
| --- | --- |
| 无权限、未登录或设置入口缺失 | 区分明确权限证据与未知；提示核对账号、仓库或适用条件，不反复提示点击不可用入口 |
| 换仓库、无关页或多个同名目标 | 停止原步骤指示，明确当前目标；返回已知页面或由用户明确切换任务，不迁移原成功证据 |
| 目标消失或定位不唯一 | 不在旧坐标或任意候选上高亮；等待／重新定位／求助，仍不明确则暂停 |
| 部署失败或取消 | 指向本次工作流的可见结果；错误详情缺失时说明不能确定根因，不自动重跑 |
| 外部部署等待或站点暂不可用 | 提供复查与暂停；等待本身不代表配置错误，模型请求超时阈值不用于判断部署失败 |
| 模型不可用、证据不足或页面含指令性文字 | 保留固定步骤和规则检查；页面文字只作为数据，模型回答不能改变验证状态 |
| 暂停、关闭引导、刷新后继续 | 同一浏览器会话内恢复目标和进度，重新核对页面和证据；迟到消息不推进已退出或不相符的任务 |

## 6. 非功能需求与验证口径

| 编号 | 首版要求与候选参数 | 验证方式／后续落定 |
| --- | --- | --- |
| NFR01 结果可靠性 | 正反例必须区分待保存、部署中、其他提交／run、旧内容、过期、读取失败和目标未知；证据不足不得误报系统已验证 | T03 定义规则，T05 以预先固定的正反例逐项记录实际结果；产品实现后纳入验收测试 |
| NFR02 响应与可取消性 | 原草案候选目标：页面和目标就绪后，本地步骤更新 p95 ≤ 500 ms；远端处理 1 秒内显示等待，30 秒后可超时／重试／退出。目标已失效时先撤销旧指示，再等待异步核对，不能把 500 ms 当作容许错误指示停留的时间。参数待校准，外部网站加载和部署等待另计；取消后迟到结果不推进任务 | 固定环境和起止点，每类至少采样 30 次；失效检测、旧指示撤销和新目标就绪后显示分别计时，Q10 落定阈值与采样方案 |
| NFR03 页面数据控制 | 采集限于用户开启的任务和必要页面范围；密码、令牌、Cookie 和无关内容不进入默认上下文／日志；附件可预览删减，清空范围可见；暂停／退出停止约定采集与推进 | 用含测试敏感字段的样例检查实际请求、存储和日志；过滤由程序控制，不能只依赖模型提示；Q06/Q09 落定字段和保留方式 |
| NFR04 权限隔离 | 首版区分网站授权、任务目标和平台数据访问；不同任务／对象的观察不得串用。若保存服务端会话或反馈，不能通过替换 ID 越权访问；完整作者／管理员权限随其功能交付 | 本地任务隔离与服务端对象访问分别做反例；认证及存储范围由 Q01/Q09 明确 |
| NFR05 可恢复与可追溯 | 目标、教程版本、步骤及必要观察可关联；同一会话内的关联标签页可共同参与任务，每次仍需核对页面角色、对象与有效性；重试不代替用户重复保存／发布；浏览器重启后提示重新开始 | 检查整页导航、无刷新 URL／DOM 变化、同页／新标签打开站点、并行任务、后台进程重启及迟到响应；Q05 定义文档／导航身份，旧页面消息不能覆盖新页面结果 |
| NFR06 易用性与验证透明度 | 中文指引与当前可见目标对应；高亮配说明且不挡关键操作；暂停、退出、求助可找到并可键盘操作；系统验证、用户确认和待确认可区分 | T04 以可操作原型开展形成性试用，记录定位、理解、误操作及人工帮助；第一阶段反馈作为输入，后续原型另取得反馈 |

## 7. 信息与外部交互要求

| 教程定义 | 任务、网站与适用条件、步骤目的和说明、目标依据、前后置条件、异常分支、来源与版本；能由运行机制读取与检查 |
| 任务参数 | 仓库、目标分支／目录、预期版本和内容、确认中的站点地址；与某个实验的固定值分开 |
| 页面观察 | 所属任务、页面与对象、采集时间、必要结果与来源、是否读取失败／已失效；未知项保留未知 |
| 会话进度 | 当前任务与教程版本、关联标签页及其页面角色／目标对象、文档或导航身份、当前步骤、暂停／恢复信息、结果类型及相关证据；区分任务进度与观察有效性 |
| AI 答疑 | 输入为用户问题、当前步骤、必要观察和来源；输出为解释／建议及其依据和不确定性，不返回可直接覆盖状态的权威结论 |
| 最简反馈 | 任务／步骤／教程版本、用户描述及经用户检查的附件；存储与提交方式见 Q09 |

界面需要提供进入任务、页面内指示、步骤说明、进度／结果、求助、暂停／退出及反馈能力。侧边栏、浮窗或组合形式在 Q07 比较。权限授予、脚本注入和任务开始／停止分别设计；不得假定同源刷新必然使 activeTab 授权失效，也不得把该授权外推到所有标签页与跨源页面。

导航需覆盖整页加载、无刷新 URL／DOM 变化，以及发布站点在当前或新标签页打开。跨标签关联不能仅凭域名或一个 taskId 即接受观察，应同时核对目标仓库／站点路径、页面角色和当前文档／导航身份。

检测到当前目标失效、任务／页面上下文切换或重新定位请求已经使旧定位无效时，先撤销旧高亮，显示核对中或等待提示，再执行异步核对。仅滚动时若目标仍有效可更新位置；仅请求 AI 解释时可保留有效高亮，不暂停正常操作。具体检测与渲染时限由 Q07/Q10 定义，不承诺零延迟。
