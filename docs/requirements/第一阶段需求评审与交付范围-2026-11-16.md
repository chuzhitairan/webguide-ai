## 2. 首个版本的验收工作细则

目标使用者：已登录 GitHub、有可发布 Pages 的练习仓库，但不熟悉发布操作的人。目标任务：把简单静态首页从明确的分支和目录发布，并确认预期内容可访问。

建议首轮只覆盖分支发布和简单首页。自定义域名、复杂构建与任意仓库通用能力留待扩展；支持的浏览器、页面语言、仓库选择方式和前置准备范围仍需设计与验证，不能根据当前固定仓库实验推定已支持。

| 验收项 | 用户应能做到／系统应表现为何 | 需求对应 |
| --- | --- | --- |
| A01 进入任务 | 理解教程目标、适用条件和当前目标仓库；不符合条件时看到说明 | FR01–FR03 |
| A02 跟随操作 | 全程在网页内可视化指示当前操作目标，目标明确时必须定位并高亮；说明本步操作与原因，由用户操作网站；无法定位时明确提示 | FR04、FR09；D06 |
| A03 区分中间状态 | 区分发布源未启用、待保存、部署等待和结果待确认；不把选择分支或点击 Save 当作完成 | FR05 |
| A04 检查最终结果 | 将发布源、关联部署及目标页面内容结合判断；证据不足保持待确认；用户确认与系统验证分别标明 | FR05、NFR01 |
| A05 处理偏离与阻塞 | 换仓库、控件缺失、部署失败或内容不符时停止错误推进，说明观察到什么以及下一步 | FR06、FR10 |
| A06 暂停与继续 | 可暂停、退出和继续；恢复时重新核对目标与当前页面，明确哪些进度可恢复 | FR07、FR08 |
| A07 可核对的解释 | 当前步骤及关键概念有解释和来源；未接入模型的说明不能冒充 AI 实时推理；模型接入范围仍待设计 | FR09、NFR01 |
| A08 数据与反馈 | 明确采集范围和必要权限；能记录当前步骤卡点，附件由用户检查；不采集无关信息 | FR18、NFR03、NFR06 |

这些是首轮的行为工作细则，不表示上述完整 FR 已实现。尤其当前实验只有固定练习对象、手动读取和会话观察，尚未提供完整教程、高亮、暂停恢复或模型问答。D05 已确定模型职责，D08 已确认首版范围；可执行细则见[Pages 首版验收清单](Pages首版验收清单-2026-11-16.md)，具体界面和实现方式留待设计。

第一阶段退出条件：确认用户问题与首轮交付目标；关键完成条件清晰；核心技术有足够证据支持继续，或已接受明确降级方案；至少一次真实引导体验留下反馈；风险、未知和后续验证安排可追踪。无需完成所有场景、全部异常、正式系统环境和全部自动化测试。

若实际扩展不能可靠取得必要结果，应先缩小系统验证声明或调整观察方案，再进入实现；浏览器操作工具读不到弹窗只说明当前调试通道受限，不能据此判断扩展失败。

## 4. 最小引导体验的记录方式

先用人工说明或简单原型，安排一次获授权的练习任务。明确初始状态和参与者经验，逐步记录“给出的指引、用户实际动作、卡点、人工补充、最终结果、用户如何理解完成”。结束后询问哪些步骤仍不明白，再修改教程。

首位参与者可以是发起人，但发起人已经熟悉本次练习站点，必须记录这种熟悉程度；不能把熟练后的成功当作新手效果。首次探索性试用只帮助发现问题，不宣称效果提升或总体成功率。若以后比较普通文字说明与现场引导，应安排不同且可比的任务，避免同一任务先后重复带来的学习效应。

| 时点 | 环境工作 | 目的 |

| 第二阶段开头：架构设计与开发准备 | 明确技术栈，建立正式工程、构建、配置、测试入口及基础 CI；评估独立浏览器自动化测试环境 | 形成可重复的开发与验证流程 |
| 随后续版本交付 | 测试部署、发布、运行监测和维护环境 | 支持可交付版本运行 |

独立自动化测试环境已有官方工具线索，但当前会话没有验证其可执行性，不承诺已能自动运行。眼下由用户代测，不以自动化环境完全搭好作为第一阶段结束的前提。不要复制个人浏览器配置或登录凭据充当测试环境。
