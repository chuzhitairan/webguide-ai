# WebGuide AI 版本交付范围

日期：2026-11-17。依据：[整体 SRS v0.2](WebGuideAI-SRS-v0.2.md)、[发起人决定 D01–D11](第一阶段需求评审与交付范围-2026-11-16.md)。本表表达交付安排，不是完整系统的能力重要性排序；后续增量尚未承诺固定版本号与日期。

更新：发起人已决定以 **GitHub 小组协作入门替代 Pages，作为首个交付及优先展示场景**。依据、建议切片与设计影响见[场景调整记录](首场景调整-GitHub协作-2026-11-17.md)。此前 Pages 的细则与实验保留原义。

## 1. 已确认方向与首场景草案

具体路径、结果判定和 SC02-AC01–SC02-AC14 见 [GitHub 协作首场景规格 v0.1](GitHub协作首场景规格-v0.1.md)。首场景与提交段方向已确认，新增验收细则为设计输入草案。

| 项目 | 范围与限制 |
| --- | --- |
| 用户任务 | 帮助不熟悉 GitHub 协作的成员理解 Issue／PR／Project；首段草案为认领 Issue、创建独立工作分支、修改指定文档并发起可评审 PR |
| 运行基线 | 桌面 Edge，英文 GitHub 页面，中文引导与答疑；页面翻译及其他语言组合单独验证 |
| 目标参数 | 目标仓库、Issue、当前成员、指定文档及基准／来源分支；创建后关联实际 PR。参数确认与身份关联规则在新场景规格中定义 |
| 核心能力 | 页面内可视高亮、规则验证、当前步骤 AI 解释答疑、偏离／阻塞处理、同一浏览器会话内暂停继续与最简反馈 |
| 结果核对 | 核对任务对象、实际认领、文档修改、提交与实际 PR 的关联；Open 非 Draft 且必要条件满足时标为提交段通过、等待评审。Draft、关闭、合并及请求修改分别显示；详细条件见 SC02 第 4 节 |
| 教程准备 | 项目维护者提供可维护的 GitHub 协作教程；首版仍不要求完整作者平台 |
| 恢复边界 | 同一浏览器会话，恢复时重查；浏览器重启后提示重新开始，不承诺跨设备恢复 |
| 建议的切片边界 | 已登录且已获仓库写权限，在浏览器中完成简单文档协作；评审合并可另成角色段落。Git 命令行、复杂冲突、Fork 贡献、完整看板管理和教程作者平台随后安排 |

首场景和展示优先级已确认；路径与验收已形成 SC02 草案，尚未运行验证或逐项定稿。整体 FR01–FR10 拟在新场景内实现，FR18 仅实现最简反馈。整体 FR17 的广场检索、FR19 的完整平台身份与 FR20 的维护后台不因首版有任务入口、授权或日志就视为已交付；相应数据与对象隔离约束仍适用。

## 2. 后续完整系统建设范围

当前先后关系调整为“GitHub 协作引导闭环 → 教程创建与维护”。Pages 保留为已有验证场景及后续教程候选，其他具体增量的组合与顺序可根据实际验证调整。下表是完整能力分组，表中先后不作为新的排期批准。

| 能力组 | 整体需求与验收 | 需要交付的业务闭环 |
| --- | --- | --- |
| 教程获取与编辑 | FR11–FR14；AC11–AC14 | 示范录制、资料生成和受控探索分别进入有来源和缺口的草稿，经作者编辑补齐；三种入口的实现时点可分别安排 |
| 教程验证、发布与发现 | FR15、FR17、FR19；AC15、AC17、AC19 | 有权作者检查、验证并发布固定版本；用户能按任务找到适用且可启动版本 |
| 维护与反馈处理 | FR16、完整 FR18、FR20；AC16、AC18、AC20 | 反馈接收、调查、修订、复核与处置结论可关联，支持撤下／回退及运行会话影响处理 |
| 引导适配与更多场景 | FR01–FR10 在新增范围内；AC01–AC10、NFR07 | 在明确网站、页面和任务范围内复用通用机制，验证专有前提与结果；Pages／Figma 保留为后续候选，不承诺同时交付 |

每个增量需要明确实际支持范围、需求子集及验收依据，不能只按功能名称勾选全部 FR 完成。O01–O06 在受影响实现与验收前按整体 SRS 指定时点处理。

## 4. 主动复用与实施关系

每个增量设计时比较直接依赖、改造模块、借鉴机制和自行实现，沿用[现有 9 个项目的调研结果](../../research/notes/WebGuideAI-开源项目调研.md)。复用选择以需求适配、许可、固定版本、集成及维护成本为依据；需求重合是可利用的基础，不作为删功能或从零重写的理由。

技术栈已有 TypeScript／React／WXT 与 Node.js／Fastify 的设计方向，见[工程配置](../design/WebGuideAI-工程配置与开发方式-v0.1.md)；正式产品工程尚未创建，模型提供方及实际依赖接入仍待执行。此次优先级调整不改变整体产品目标，也不使已有 Pages 适配器自动获得协作场景的能力。
