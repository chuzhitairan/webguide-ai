# WebGuide AI 版本交付范围

日期：2026-11-17。依据：[整体 SRS v0.2](WebGuideAI-SRS-v0.2.md)、[发起人决定 D01–D11](第一阶段需求评审与交付范围-2026-11-16.md)。本表表达交付安排，不是完整系统的能力重要性排序；后续增量尚未承诺固定版本号与日期。

## 1. 已确认的首个交付范围

| 项目 | 范围与限制 |
| --- | --- |
| 用户任务 | 已登录、具备必要权限且已有简单静态首页的用户，完成指定仓库的 GitHub Pages 分支发布或核对已有发布结果 |
| 运行基线 | 桌面 Edge，英文 GitHub 页面，中文引导与答疑；页面翻译及其他语言组合单独验证 |
| 目标参数 | 可指定符合条件的仓库、分支、目录、预期版本与内容，不写死实验仓库；用户不必自行提供提交 SHA 才能开始 |
| 核心能力 | 页面内可视高亮、规则验证、当前步骤 AI 解释答疑、偏离／阻塞处理、同一浏览器会话内暂停继续与最简反馈 |
| 结果核对 | 关联目标配置、部署 run／提交及预期站点内容；证据不充分保持待确认；系统验证与用户确认分别标示 |
| 教程准备 | 项目维护者提供可维护的 Pages 教程；可维护不等于首版已具备完整作者平台或在线编辑发布功能 |
| 恢复边界 | 同一浏览器会话，恢复时重查；浏览器重启后提示重新开始，不承诺跨设备恢复 |
| 不在本次交付内 | 注册账号、代写首页、复杂构建、自定义域名、完整教程获取／作者平台及 PR／Figma 等额外场景 |

整体 FR01–FR10 在上述 Pages 范围内实现，FR18 仅实现最简反馈。整体 FR17 的广场检索、FR19 的完整平台身份与 FR20 的维护后台不因首版有任务入口、授权或日志就视为已交付；相应数据与对象隔离约束仍适用。

## 2. 后续完整系统建设范围

已确认的先后关系是“Pages 引导闭环 → 教程创建与维护”，其他具体增量的组合与顺序可根据实际验证调整。下表是完整能力分组，表中先后不作为新的排期批准。

| 能力组 | 整体需求与验收 | 需要交付的业务闭环 |
| --- | --- | --- |
| 教程获取与编辑 | FR11–FR14；AC11–AC14 | 示范录制、资料生成和受控探索分别进入有来源和缺口的草稿，经作者编辑补齐；三种入口的实现时点可分别安排 |
| 教程验证、发布与发现 | FR15、FR17、FR19；AC15、AC17、AC19 | 有权作者检查、验证并发布固定版本；用户能按任务找到适用且可启动版本 |
| 维护与反馈处理 | FR16、完整 FR18、FR20；AC16、AC18、AC20 | 反馈接收、调查、修订、复核与处置结论可关联，支持撤下／回退及运行会话影响处理 |
| 引导适配与更多场景 | FR01–FR10 在新增范围内；AC01–AC10、NFR07 | 在明确网站、页面和任务范围内复用通用机制，验证专有前提与结果；PR／Figma 保留为候选，不承诺同时交付 |

每个增量需要明确实际支持范围、需求子集及验收依据，不能只按功能名称勾选全部 FR 完成。O01–O06 在受影响实现与验收前按整体 SRS 指定时点处理。

## 4. 主动复用与实施关系

每个增量设计时比较直接依赖、改造模块、借鉴机制和自行实现，沿用[现有 9 个项目的调研结果](../../research/notes/WebGuideAI-开源项目调研.md)。复用选择以需求适配、许可、固定版本、集成及维护成本为依据；需求重合是可利用的基础，不作为删功能或从零重写的理由。

当前未选择正式技术栈、模型提供方或具体依赖，也未因此创建工程或扩大浏览器权限。交付安排改变时更新本表；整体业务规则、确认范围或能力发生改变时同步修订 SRS 与验收条件。
