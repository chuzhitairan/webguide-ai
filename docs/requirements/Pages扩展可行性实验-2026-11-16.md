## 修正上一轮的判断依据

本次看到设置页同时显示“Your site is live at …”和“currently being built from the main branch”，而对应工作流已经 Success。因此后一句描述不能单独证明实时构建中。

上一轮保存后的现场确有工作流构建过程，但仅凭该段文字推断实时状态不充分。需求与实验改为：设置页只能证明来源与已报告的发布信息；实时排队、运行、失败和成功以具体工作流为依据；最终还需访问预期站点内容。

首轮最小可行性实验的手工采集现可收尾。用户已明确允许在当前 Edge 启用开发者模式并加载 v0.0.1，允许读取指定练习页。2026-11-16 操作工具拒绝访问扩展管理页并禁止绕过；随后用户手动加载。网页接口无法提供扩展弹窗，这是调试通道限制，不据此判断扩展失败。当前约定由用户代为操作和提供结果，助手核对与排查，不主动使用桌面控制。见[手动实测与截图清单](../../experiments/pages-state-spike/手动实测与截图清单.md)。

## 首轮结论与后续验证

现有用户代测文本支持：在本次固定仓库、提交、站点及已加载的 Edge 扩展中，可以手动采集并关联发布源、工作流和站点内容；三项齐全才报告通过，单项不足保持未完成，范围外页面被拒绝且本次保留已有观察。这些证据足以支持继续进行首版需求与交互设计，无需先搭完整后端或继续重复成功路径。

不能由此推定任意仓库通用、全部异常可靠、状态持续实时、跨会话恢复或新手使用效果。前次空数组原因保持未确定，不基于猜测修改代码。后续安排沿用需求评审中的阶段划分：

| 待核对事项 | 后续验证时点 |
| --- | --- |
| 未配置、未保存、运行中、失败、旧内容的真实扩展输出 | 对应状态处理实现与验收时，以获授权练习和可控样本分别记录 |
| 单独重开、过期、权限拒绝与重载后的恢复边界 | 第二阶段建立可重复工程验证后，补充生命周期测试 |
| 浏览器、语言和页面结构变化 | 设计阶段明确支持范围，首版交付前核对范围内兼容性 |
| 指引是否易懂、用户能否判断完成 | 第一阶段剩余的真实引导体验；不能由本次采集实验替代 |

首个可交付版本的顺序已确认为 Pages 引导闭环，随后加入教程创建与维护，见[需求评审与交付范围](第一阶段需求评审与交付范围-2026-11-16.md)。扩展实验收尾提供可行性证据，不等于首个产品版本或真实引导体验已经完成。
