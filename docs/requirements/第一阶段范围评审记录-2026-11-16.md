## 3. 可供确认的首版范围

建议用以下范围进入第二阶段设计，不要求现在实现：

1. 桌面 Edge、英文 GitHub 页面为首轮支持基线，指引与问答使用中文；其他语言和翻译组合单独验证。
2. 面向具备权限、已准备简单静态首页的仓库，完成 Pages 分支发布；支持指定合适的仓库，不仅限于当前实验仓库。
3. 页面内可视指引与高亮、规则检查、当前步骤 AI 答疑、同一浏览器会话内暂停继续和最简反馈构成首版闭环。
4. 验收包括首次发布、已有结果核对和阻塞／偏离处理；教程创建维护、其他网站场景及复杂发布配置随后推进。

上述范围对应 B01–B12。框架、数据库、模型提供方、权限实现及视觉样式在下一阶段比较方案并形成设计，不在此次范围评审中预先认定。

## 4. 评审结论与遗留项

助手检查未发现阻止按上述范围开展设计的需求矛盾；不代表技术风险已经解决。B03/B06/B09 是助手提出的具体化建议；发起人随后确认了上述四点首版范围。B01–B12 用作设计与后续验收的工作细则，具体界面、字段、时限和实现方式仍可在设计中细化，不声称发起人已逐行审核全部技术细节。

后续必须跟踪：完整发布状态的真实扩展覆盖、目标版本与内容关联、定位及高亮可靠性、恢复生命周期、模型上下文与凭据、支持矩阵、独立浏览器测试环境可执行性。已有[阶段总结](第一阶段总结与设计输入-2026-11-16.md)记录设计输入，无需重复现有成功路径或先搭完整系统才能结束需求阶段。

发起人确认记录：2026-11-16，通过范围确认问题明确选择“按此范围进入设计（推荐）”。问题列明 Edge 英文页面／中文引导、可指定仓库的简单 Pages 分支发布、页面内高亮／规则验证／AI 答疑／会话内恢复／最简反馈，以及首次发布／核对／阻塞处理与后续教程维护顺序。此项是对该具体范围的确认，不仅是同意继续评审。
