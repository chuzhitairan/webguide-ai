# 第 1–2 次课需求调研计划

整理：2026-11-17。前期工作日期来自已有记录；下列未来安排是建议，由组长与成员确认可用时间。

## 目标与对象

围绕最近一次真实网页任务了解目标、初始条件、卡点、尝试、后果和完成依据；补充教程制作／维护经历。优先找近期用过 GitHub 或 Figma 的新手，以及实际帮助过别人的熟练用户。采用 15–20 分钟半结构访谈，可请对方回忆或自愿展示已有经历，无须新一轮扩展调试。

建议最小样本为 2 位独立参与者：新手 1 位、熟练用户或维护者 1 位。若能兼顾更多角色则补充；这是本项目建议，不是教师规定的人数或代表性统计样本。

## 四个同量级、可验收工作包

组长承担需求整合、关键决定与主线实现。其余四位各认领一个约 1–2 小时的有限工作包；不按熟悉程度设置隐性主力。实际时间和贡献如实记录，超出预估由组长协助收敛。

| 工作包 | 产出 | 验收条件 |
| --- | --- | --- |
| A 新手访谈 | 一份真实纪要与 3–5 条发现 | 有参与同意、具体经历、原话与推论分开；无预填结论 |
| B 熟练用户访谈 | 一份真实纪要与 3–5 条发现 | 同 A；包含实际答疑或教程维护案例，若无经历写明 |
| C 公开来源核对 | 核对报告中的 5 个关键来源并提修订 PR | 每项列链接、任务、卡点、结论是否有支持；失败或不一致有记录 |
| D 需求与讲稿核对 | 对 14 条故事和讲稿列检查结果并提修订 PR | 核对角色、验收、首版范围与证据；至少记录具体检查项，不要求凑缺陷 |

四个包均须由认领人理解并提交真实工作，组长不代写后冒用其身份。后续 PR 数量通过持续任务积累，不拆空白 PR 凑数。

## 访谈及报告完成条件

实际访谈有日期、匿名角色、记录者、参与同意、具体经历和必要原话；参与者可拒答或停止。没有得到回答的字段写未知。公开仓库发布前，去除联系方式、真实姓名、私有仓库信息和未经同意的截图，必要时只提交脱敏摘要。

报告区分资料事实、参与者自述、团队推论与待验证问题。访谈反例进入结论；需求发生变化时关联故事和 SRS 的变更。报告 PR 经另一位成员实际 Review、修订并合并后，才完成课程要求的提交过程。
