## 交付优先级与工作量初估

P0 表示当前 GitHub 协作首版必需；P1 表示随后教程创建与维护增量；P2 表示更后续的增强能力。优先级表达交付顺序，不改变完整系统需求的重要性。SP 使用 1／2／3／5／8／13 的相对规模，综合实现、集成与验证的不确定性，不等于天数或成员绩效。

下表为助手提出、待组长核读的初估，按“估算切片”计；同一故事的剩余能力另估。多个故事共享协调器、页面采集和模型网关，点数不能直接相加承诺工期。13+ 项先拆分、明确范围后再估；实际开发取得数据后修订。

### US01：找到适合当前任务的教程

- 交付范围：首版支持 GitHub 协作任务入口与匹配；通用检索在后续交付。

作为学习者，我希望用自己的话描述目标并查看适用教程，以便从当前任务开始。

- 对应：FR01、FR02、FR17；UC01、UC02、UC17。
- Given 用户描述目标且存在适用教程，When 发起检索，Then 展示教程目标、网站、适用条件与版本，选择后开始；Given 没有适用结果，Then 明确说明并转入 FR10，不伪造匹配项。

### US02：先知道当前条件能否操作

- 交付范围：首版 GitHub 协作 SC02 范围。

作为学习者，我希望知道模式、权限或对象选择是否满足条件，以免照着不存在的入口反复尝试。

- 对应：FR03；UC03。
- Given 某必要条件已观察为不满足，When 开始或继续教程，Then 先解释阻塞并给出适用的调整路径；条件不可读时标为未知，不当作满足。

### US03：清楚看到本步的目标与原因

- 交付范围：首版 GitHub 协作 SC02 范围。

作为学习者，我希望在当前页面知道应操作哪个控件及原因，以便理解并完成这一步。

- 对应：FR04、FR09；UC04、UC09。
- Given 有唯一可确认的目标控件，When 展示步骤，Then 高亮与文字指向同一控件，用户仍自行执行；如果存在多个候选，Then 先消除歧义，不任意选取第一个。

### US04：知道任务是否真正完成

- 交付范围：首版 GitHub 协作 SC02 范围。

作为学习者，我希望系统区分中间动作与最终结果，以免遗漏最后一步。

- 对应：FR05；UC05。
- Given 仅点击保存或添加草稿评论，When 检查结果，Then 保持处理中或未完成；只有对应任务结果满足完成条件，才记录系统验证成功，并保留依据。用户确认与自动验证分别标记。

### US05：卡住后能重新找到适合当前状态的路径

- 交付范围：首版 GitHub 协作 SC02 范围。

作为学习者，我希望找不到控件或点偏后得到新的判断，以便恢复操作。

- 对应：FR06、FR09、FR10；UC06、UC09、UC10。
- Given 目标不存在、不可用或用户报告指引不符，When 请求帮助，Then 重新检查当前状态并给出有依据的恢复建议；仍无有效路径时说明缺失信息并允许退出，不无条件重复原指令。

### US06：随时暂停并从实际进度继续

- 交付范围：首版限同一浏览器会话；浏览器重启后提示重开。

作为学习者，我希望暂停、退出或刷新后能够理解当前进度，以便按自己的节奏操作。

- 对应：FR07、FR08；UC07、UC08。
- Given 已记录部分进度，When 暂停或恢复，Then 暂停时停止任务采集与自动推进，恢复时核对网站、任务对象与教程版本；状态已改变则重新判断，不盲目跳到旧步骤。明确结束后停止该会话的页面采集。

### US07：把一次示范变成教程草稿

- 交付范围：后续：教程创建。

作为熟练用户，我希望主动录制一次示范，以便复用已有操作经验。

- 对应：FR11；UC11。
- Given 作者已选择录制范围，When 开始、完成并停止示范，Then 生成可编辑的有序草稿，记录已采集与未能采集的步骤；停止后不再继续录制。

### US08：修正步骤与成功条件

- 交付范围：后续：完整作者编辑；首版由维护者准备教程文件。

作为教程作者，我希望编辑操作、前提和结果检查，以便教程表达完整流程。

- 对应：FR12；UC12。
- Given 作者可编辑某草稿，When 调整步骤并保存，Then 草稿保留修改，缺失必要条件或完成检查的步骤可被识别；已发布版本不被草稿修改覆盖。

### US09：依据官方资料生成可审核教程

- 交付范围：后续：文档生成。

作为教程作者，我希望用文档和目标生成草稿，以便减少手工整理步骤的工作。

- 对应：FR13；UC13。
- Given 可读取的文档与明确任务，When 发起生成，Then 返回来源、适用条件、候选步骤和待核实项；资料不足时指出缺口，结果保持草稿，生成失败可重新尝试而不覆盖现有版本。

### US10：让 Agent 在限定环境探索

- 交付范围：后续：受控探索；不作为首版前置。

作为教程作者，我希望限定练习环境、目标和操作边界后让 Agent 尝试流程，以便补充文档未写清的操作。

- 对应：FR14；UC14。
- Given 已指定隔离练习环境、允许范围和停止条件，When 开始探索，Then 操作留有轨迹，达到限制或越界前停止；未达到任务目标时记录失败，不生成“已验证成功”的结论。

### US11：先验证，再发布教程

- 交付范围：后续：完整验证发布平台；首版维护者准备和检查教程。

作为教程作者，我希望检查步骤可执行性和完成条件后发布，以便学习者知道教程是否经过验证。

- 对应：FR15；UC15。
- Given 有草稿及声明的验证环境，When 校验和人工检查完成，Then 记录通过或失败与依据，按 SRS BR04 继承仍适用的验证或重验受影响部分；必要验证未通过的保持草稿，发布形成可识别版本。

### US12：更新教程并保留历史

- 交付范围：后续：完整版本维护。

作为维护者，我希望用新版本修复失效步骤，以便控制变更并保留可用历史。

- 对应：FR16；UC16。
- Given 有已发布版本，When 创建修订或回退，Then 保留历史与变更原因；运行中的会话仍关联原版本，若需切换则说明影响并重新检查进度。

### US13：反馈卡点并跟进维护

- 交付范围：首版最简反馈；后续维护处理闭环。

作为学习者，我希望提交卡住的位置和实际情况；作为维护者，我希望看到与版本关联的反馈，以便定位并处理问题。

- 对应：FR18、FR20；UC18、UC20。
- Given 会话停在某一步，When 用户检查附加内容后提交反馈，Then 记录任务、步骤、教程版本和问题描述；维护者可关联修订与处理结论，统计不暴露无关页面内容。

### US14：按职责使用平台功能

- 交付范围：后续：完整平台权限；首版仍须保护会话及目标对象边界。

作为平台用户，我希望编辑和管理行为受到权限约束，以便维护自己的教程与记录。

- 对应：FR19、FR20；UC19、UC20。
- Given 用户没有目标教程的维护权限，When 通过界面或直接请求修改、发布或撤下，Then 服务端拒绝且内容不变；获授权者操作成功并留下对应记录。管理员也不因此获得用户目标网站的账号权限。

## Issue 化与检查

创建 Issue 时一条故事一个入口，保留 US 编号、对应 FR/UC、交付范围与验收条件，再按实际版本拆分有限实现任务。US13 的学习者提交与维护者处理分别列验收路径，首版只认领最简反馈子集。已有同一故事的 Issue 则更新，避免重复。

用例、非功能要求与追溯以 SRS 为准；课程检查时间参考课程表，Issue 化和分派按实际实现需要推进。负责人与链接见 [团队台账](团队与过程台账.md)。
