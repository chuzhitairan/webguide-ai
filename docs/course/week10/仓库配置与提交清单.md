## 1. 目标配置

- 仓库：`chuzhitairan/webguide-ai`，私有，教师查看需有权限。
- 默认分支：`main`；先建立最小初始化提交，再配置 PR 保护，后续实质内容走分支。
- PR：至少另一位成员批准；不允许直接推送受保护分支，不启用自动合并绕开评审。
- Projects：`WebGuide AI — Course`，状态为 Backlog／Ready／In progress／In review／Done；一个任务只有明确验收后进入 Done。
- Milestone：`W10 调研与初步需求`（11-20）、`W11 SRS 评审`（11-27）；产品增量 Milestone 在迭代计划确认后另建。
- 模板：根目录 `.github/ISSUE_TEMPLATE/` 与 `.github/pull_request_template.md`。
- 成员：组长手动添加其余四位；教师若检查私有仓库，另按其指定方式提供访问。

当前无产品工程和 CI，不设置不存在的必需状态检查。正式加入构建／测试工作流后，再选择实际存在且可通过的检查为必需。

## 3. Issue 与 PR 批次

选题 Issue 已说明产品目标、三种角色、整体范围、首版 Pages 闭环、预期成果和风险。组长按课程入口向教师报送，并记录意见。

调研与故事 PR 建议统一提交本次课程包；关联“调研报告与用户故事”任务 Issue，说明独立访谈未完成，不把草稿当成已完成调研。成员实际访谈与核查各提交有限 PR，合入调研分支或在后续 PR 补入；报告最终满足本周要求后由另一成员批准合并。

用户故事 US01–US14 分别建 Issue，保留对应 FR/UC 和交付范围。作者平台与受控探索故事放 Backlog，不误设为 W10 要完成的产品实现。故事初稿可以先进入课程报告，完整 Issue 化按第二次课后的要求继续。

## 4. PR 评审交接

请组员在实际 PR 中完成：核对至少一组原始证据与需求推论、检查故事验收与范围、确认访谈事实及公开同意、指出遗漏或说明认可依据。作者实际修订后再批准。组长自己提出的 PR 需要其他成员 Review；组长不能代批准。

本次配置未遇到付费拦截。仓库和看板均为私有；组长添加成员后还需确认其看板访问，以及教师的材料查看方式。

已执行本地核验：课程包相对链接检查；14 条故事编号与 Given/When/Then 检查；`git diff --cached --check`；两个既有实验共 26 项 Node 自动测试通过。原始教师资料、上游学习副本、临时文件和环境配置未提交。后续记录更新单独提交到同一 PR。
