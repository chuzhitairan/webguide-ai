# WebGuide AI 需求调研报告

版本：课程整理稿 v0.1，2026-11-17。适用：第 2 次课调研讲解与组内审阅。独立用户访谈结果待补入第 7 节。

## 1. 调研目标与项目方向

WebGuide AI 面向带着具体任务使用网页的用户：在当前页面指出操作目标、解释原因、检查结果，并帮助作者建立和维护可复用的教程。完整系统覆盖教程获取、编辑验证发布、现场引导、反馈修订和失效处理；GitHub Pages 是首个交付场景。

本次调研回答三件事：用户在什么任务中卡住，已有工具可以复用什么，以及首个增量应验证什么。商业付费模式暂不纳入本轮决策。

## 2. 干系人与业务目标

| 干系人 | 典型目标与困难 | 本轮证据 |
| --- | --- | --- |
| 操作用户／学习者 | 完成具体网页任务；找不到入口、不明白前提或不知道是否成功 | GitHub/Figma 公开求助；发起人反馈与 Pages 操作记录 |
| 教程作者／维护者 | 把经验变成教程，发现并修复过时内容，减少重复答疑 | 文档截图维护讨论；GitHub 维护者公开回复；作者独立访谈待补 |
| 平台管理员 | 控制平台内内容和权限，处理失效与问题记录 | 整体系统治理需求；尚无管理员访谈 |
| 课程团队与教师 | 持续交付可运行系统，并保留需求、评审、贡献与验证证据 | 课程资料及已确认的项目方向 |

角色可由同一人兼任。产品角色与组内开发、测试岗位分别管理。

业务目标及后续验证方式：

- 学习者能把说明对应到当前页面：观察能否找到目标、是否需要额外定位提示。
- 学习者能区分操作与结果：通过未保存、等待、部署失败、版本不符等样例检查，是否错误宣布完成。
- 遇到阻塞能得到合理下一步：观察是否重复无效操作，能否说明缺少的条件。
- 作者能维护教程：后续记录制作、修改和重新验证一份教程的实际过程与耗时。

目前没有取得产品效率提升、成功率或维护时间下降的对照数据，以上是目标和验证方向。

| 发现 | 具体证据 | 需求推论 | 对应故事／需求 |

## 6. 场景选择与阶段结论

首个增量选择 GitHub Pages 分支发布／已有结果核对：有相对清晰的前提、跨页流程和完成证据，便于先完成引导闭环。适用用户已准备简单静态首页、拥有所需权限，在桌面 Edge 的英文 GitHub 页面接受中文引导。

当前已确认的首版能力是页面高亮、规则检查、当前步骤答疑、偏离／阻塞处理、同一浏览器会话内暂停继续与最简反馈。AI 解释证据与提出建议，确定性规则判定完成。完成核对需要关联发布配置、部署 run／目标提交和站点预期内容；单独点击 Save 或看到站点上线提示不足以证明目标版本完成。

后续建设教程录制、文档生成、受控探索、编辑验证发布和维护反馈闭环。各能力在整体需求中完整描述，交付次序单列；受控探索可以后排，不承担首轮闭环的前置依赖。详见 [SRS](../../requirements/WebGuideAI-SRS-v0.2.md)、[版本范围](../../requirements/版本交付范围-2026-11-17.md)与 [14 条故事](用户故事.md)。

实验已表明部分技术路径可行，也发现“currently being built from”不能独立当作仍在部署的反例。现有实验没有交付完整高亮产品、教程平台或独立新手试用结论。

## 7. 访谈补充与待检验假设

截至本稿，没有可确认的独立用户访谈纪要。正式提交前，由成员执行[调研计划](调研计划.md)，用[纪要模板](访谈提纲与纪要模板.md)补入以下内容：

| 记录 | 当前状态 | 补入内容 |
| --- | --- | --- |
| 新手／近期求助用户 | 待执行 | 最近一次具体任务、卡点、求助过程、如何判断完成 |
| 熟练用户／教程维护者 | 待执行 | 重复答疑、教程制作与维护经历，现有替代办法 |

重点核对：用户是否愿意在明确范围内安装／授权扩展；高亮与必要概念解释如何配合；前提检查能否减少无效尝试；作者是否真正愿意维护教程。访谈中出现“不需要”“已有办法足够”或不愿授权时同样保留，并修订需求判断。
