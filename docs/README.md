# WebGuide AI 项目文档

更新于 2026-11-26。

**当前方向**　把扩展做成 AI 浏览器导航的运行层。AI 根据当前页面选择高亮目标和提示，扩展在网页上显示，用户自己操作。总体设计已形成评审稿，涵盖自然语言目标、按需补看、稳定指引与跨站验证。[导航 Harness 设计](design/WebGuideAI-导航-Harness-设计.md)

**当前阶段**　原型已能用个人 API 密钥从扩展直连模型。下一阶段让组员独立安装并带着自己的目标试用，同时验证不同任务和页面起点的覆盖范围。[试用新引导](../README.md#试用新引导) · [第 11 周课程检查](course/week11/README.md)

## 当前进度

| 模块 | 已实现和已验证的范围 |
| --- | --- |
| 引导闭环 | 用户输入自然语言目标。模型可批量补看局部信息，扩展核对后高亮。用户推进时，已定位的屏外控件可滚入视口后直接高亮。用户操作后重新观察，并按「找到入口」「到达界面」「设置生效」各自的证据收尾。网页之外的结果可请用户确认。[导航 Harness 设计](design/WebGuideAI-导航-Harness-设计.md#54-完成要看目标原句) |
| 真实站点 | 较早一轮 GitHub 与 Figma 实测 8 次，6 次完整通过。后来验证了 GitHub 按编号找 PR，以及从列表进入详情后才完成。维基百科验证过字号生效，但固定面板的专项复测有一次停在初次定位。Figma 有一次滚动后指对但未收尾，固定观察回放未复现，保留为复测项。[PR 详情复测](design/导航Harness-真实站点验证-2026-11-23.md#从列表打开-pr-详情) · [维基百科复测](design/导航Harness-真实站点验证-2026-11-23.md#操作后优先复查) · [Figma 回放](design/导航Harness-经验对照-2026-11-24.md#滚动后的上一条指引对照) |
| 故障恢复 | 有额度时自动重试一次。最后一次请求只使用已有观察。重试仍失败时，侧栏暂停。点击「继续引导」后沿用原目标，并重新查看当前页面。构建 `673b2b8` 通过 101 项自动测试和 14 项 Chromium 浏览器回归。[故障与恢复](design/WebGuideAI-导航-Harness-设计.md#7-数据故障与调试) |
| 经验模块 | 两条本机候选和有／无经验开关已接入，默认关闭。Figma 固定页面对照两组各指对 3/6，真实维基百科对照两组均走通，现有样本尚未显示稳定收益。[首轮经验对照](design/导航Harness-经验对照-2026-11-24.md) · [经验模块设计](design/WebGuideAI-经验模块设计.md) |

扩展默认配置同济 Flash，当前试用低推理强度，按用户设置申请对应域名的访问权限。每次请求预留最多 4,096 个生成 token，扩展单次最多等 15 秒，每轮最多处理 45 秒。[模型配置](design/WebGuideAI-工程配置与开发方式-v0.1.md#6-扩展直连与模型配置) · [时限对照记录](design/导航Harness-真实站点验证-2026-11-23.md#放宽模型等待时间)

## 接下来的计划

1. **先建立一组小型跨站验收。** 固定当前构建、模型和预算，关闭经验。先用此前未试过的 GitHub PR 验证找入口，用维基百科的深色主题验证设置生效，再挑一个公开文档站试「到达指定内容」。每类换一种起点或目标说法复测，记录是否指对、终点是否真实达成、请求次数和等待时间。
2. **按验收中反复出现的缺口改进 Harness。** 优先处理误报完成和无法恢复的卡点。查明模型当时看到的页面信息、提出的决定和扩展实际显示的结果。若多个场景都缺关键结构信息，先验证是否能通过局部补看取得。无名图标或画布等信息仍缺失时，再做带编号截图的对照。
3. **用有明确卡点的任务检验经验。** 在同一任务、起点、模型和预算下比较有／无经验，优先看完成率、误指和误报，另外记录请求数与耗时。跨站共性经过复验后再进入 Harness。经验有稳定收益后，先用本机记录试验自动提炼与验证候选，再按实际共享需求安排服务器。[经验实施顺序](design/WebGuideAI-经验模块设计.md#7-实施顺序)

**既有原型**　早期实时引导验证了 GitHub 指定 Issue、README 编辑入口与 Fork 提示，也在真实 Figma 练习稿中验证了图层和自动布局开关的高亮。[原型快照与旧版运行契约](../README.md#试用旧版实时引导)
