# 浏览器扩展经验

更新：2026-11-24。以下结论来自实测和原型，旧版测试见回归索引。[原型浏览器回归索引](../design/WebGuideAI-浏览器导航原型.md#查看原型的浏览器回归)

- **动作不等于结果。** 用户点过按钮、页面出现成功词或旧流程成功，都不足以证明当前任务完成。采集并关联任务对应的配置、版本和结果；AI 解释，规则判定。Pages 页面曾在已上线时仍显示 “currently being built”，见 [Pages 实验](../../experiments/pages-state-spike/README.md)。
- **同一对象可能因配置不同而显示不同标题。** Figma 中选中同一个图层时，普通布局显示 `Layout`，启用自动布局后显示 `Auto layout`。观察阶段需保留两个状态的入口，否则模型可能把缺失的采集结果误当成页面状态。
- **按真实结构验证控件采集。** Figma 图层的图标与名称都可能标为第 1 列。识别图层时按名称检查该列的所有单元格，再确认匹配的是唯一图层。回归页复现了重复列，以及点击图层后同一设计稿的 `node-id` 变化。
- **用可见标签定位透明控件。** Figma 自动布局开关和维基百科字号选项都使用了透明输入控件。沿浏览器的 `label.control` 关联取得角色和当前状态，用可见标签定位高亮。标签改为关联别的控件时，废弃旧编号。[维基百科验证](../design/导航Harness-真实站点验证-2026-11-23.md#第三站验证维基百科字号)
- **操作后把上一步控件的最新状态放进首读。** 目标可能原先只能靠补看找到，点击后如果只采集普通摘要，模型会漏掉已生效的状态。先重查同一控件，再用本轮编号把它放到观察前面。换页或目标失效时回到常规观察。[操作后复查回归](../design/导航Harness-真实站点验证-2026-11-23.md#操作后优先复查)
- **侧栏气泡要给相邻控件留空间。** 即使点击能穿过气泡，文字和控件仍可能被盖住。Figma 导航把气泡放到图层栏或属性栏外，窗口太窄时用扩展侧栏显示提示，网页继续标出位置。
- **失效先撤销，再重新定位。** 页面隐藏、导航、目标变化或引导暂停时及时移除旧高亮；唯一且可见的目标才恢复指示。观察与迟到响应必须绑定任务及当前上下文。依据：[生命周期实验](../../experiments/extension-lifecycle-spike/README.md)、[运行契约](../design/WebGuideAI-运行契约-v0.1.md)。
- **API 能力以实际浏览器为准。** 实测 Edge 157 暴露侧栏开／关事件，关闭侧栏时连接断开触发暂停且蓝框消失；不能沿用“侧栏一定没有关闭事件”的旧说法，也不能把断连直接当成人为关闭的唯一原因。目标版本变化后复核相关行为。
- **页面已有可操作控件就可以指路。** GitHub 的链接已经可用时，浏览器可能还在等待图片等资源。当前文档有可用控件就开始观察，发生跳转时等新文档可用再接入。浏览器回归用一个故意延迟的图片覆盖这一情况。
- **整页导航按文档重连。** 同源跳转可以保留 `activeTab` 权限。刷新或整页跳转后要接上新主文档，并校验文档 ID 以防重。同文档路由变化只需重读页面。[Harness 的授权与恢复](../design/WebGuideAI-导航-Harness-设计.md#53-授权整页跳转与恢复)
- **侧栏打开记录可能缺失。** Edge 上从扩展菜单打开侧栏时，浏览器已经授予 `activeTab` 权限，侧栏却未必有相应的点击记录。此时可读取浏览器已向扩展公开的当前页地址，作为连接入口。[真实站点复测](../design/导航Harness-真实站点验证-2026-11-23.md#网络恢复后的复测)
- **行内操作单独采集。** 悬停出现的按钮、开关可以有自己的名称和编号，选中行的名称按独立的对象文字读取。这样鼠标离开图层去滚动属性栏时，仍能识别为同一选中对象。[真实站点复测](../design/导航Harness-真实站点验证-2026-11-23.md#网络恢复后的复测)
- **收尾时核对网页上的最后一个高亮。** 模型的推荐目标、完成证明里的目标和浏览器实际绘制的目标都可能不同。测到侧栏报告完成时同时核对最后的蓝框。Figma 曾在回复指向导出加号时，实际把完成高亮画到了图层行。[真实站点复测](../design/导航Harness-真实站点验证-2026-11-23.md#收尾证据里暴露的两个问题)
- **同名入口在高亮前核对所属区域。** 同时看到一个对象和一个同名按钮，仍需检查两者是否关联。正例检查控件确实在引导引用的范围内。反例保留视口外的正确入口，检验普通高亮和完成证明能否排除页面级的同名按钮。[同名入口验证](../design/导航Harness-经验对照-2026-11-24.md#同名入口的归属核对)
- **虚拟列表的搜索结果只覆盖已渲染的条目。** 视口外有些条目尚未进入 DOM，滚动后节点还可能被复用。判断时保留当前的滚动范围，并在用户滚动后核对节点现在代表的对象。[虚拟列表原理](https://web.dev/articles/virtualize-long-lists-react-window)
- **文字指引后也要接住实际滚动。** 模型可能省略滚动区域编号，用户滚动后首读也可能没有变化。文字提示期间等一次实际滚动触发再观察，有明确可用区域时沿用区域内的复查。[滚动回归记录](../design/导航Harness-经验对照-2026-11-24.md#滚动后重新观察)
- **跳转后留短缓冲，晚加载的相关控件再复核。** 预设原型在新页面和普通页面变化时使用约 180 毫秒的合并窗口，持续变化时最多等约 650 毫秒。背景加载期间保留仍可操作的高亮，只有任务相关的控件出现或改变时才把新线索交给模型，复核时沿用原提示。用户操作、目标失效或到达目标仍可推进。
- **自动回归使用独立浏览器配置与配套 Chromium。** 普通扩展标签页可自动验证后台、页面连接、高亮、暂停和界面断连。Edge 原生侧栏及权限提示保留专门验证；浏览器安装时按实际使用的 Playwright 版本取配套修订版。依据：[本机自动化预检](../design/WebGuideAI-工程配置与开发方式-v0.1.md#本机验证记录2026-11-19)。
- **实验权限和交互不能直接当正式方案。** 手动点击扩展的 `activeTab` 实验只证明相应路径，不证明跨源新标签页和持续引导。正式权限、SPA 导航、跨标签关联按[工程设计](../design/WebGuideAI-工程配置与开发方式-v0.1.md)处理。
- **先解决关键未知，再停止扩张实验。** 用户已表示手动小验证适量即可；已有证据足以选方案后，把精力转到闭环实现。需要用户操作或截图时给出明确步骤与观察点，不默认接管整个桌面。
