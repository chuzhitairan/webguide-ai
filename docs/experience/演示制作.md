# 演示制作经验

更新：2026-11-19。适用于本项目的课堂与产品介绍；当前实例见[演示材料](../course/week10/presentation/README.md)。

- **先定主线，再决定页数。** 本次有效顺序是“真实困难 → 流程与动机 → 已有能力与切入点 → 需求 → 交互 → 完整系统 → 实现与下一步”。每页承担一个作用；重复流程、独立状态表和孤立试用指标削弱衔接时，合并或删除。
- **保留用户认可的克制风格。** 深青／薄荷绿／米白、微软雅黑、充足留白、大标题和细分隔线。修改内容优先沿用现有构图；不要因为新评审建议整套换风格。
- **展示具体问题与产品行为。** 真实 GitHub 截图比抽象占位框有效；用户故事编号、内部 PR 状态和研究计数不能替代需求说明。产品界面用位置、步骤说明、规则状态和答疑入口说明价值。Pages 实验保留为技术依据，不在协作场景中突然切换演示。
- **正文自然，事实边界集中说明。** 删除“发起人真实提问”、归档式脚注及反复免责；概念界面简标“概念原型”，来源放备注。讲稿用口语，区分已有实验、拟定方案与后续工作。
- **不机械采纳外部意见。** 先判断是否改善本次汇报的整体逻辑。用户不需要备用页时，必要内容放入主线，其余舍去。
- **交付一套当前版。** PPTX、PDF、讲者备注、总览与制作源码放同一入口；同步页数、标题和链接。PPT 导出后逐页渲染查看，不仅检查 XML／坐标；没有在 PowerPoint 实测就不写“已通过 PowerPoint”。旧试稿与渲染缓存及时清理。
