# WebGuide AI 协作引导首轮工程实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 沿用当前会话逐项实现的方式，不安排并行改核心文件。

**Goal:** 建立正式工程，在自有协作模拟页跑通“认领→工作分支→编辑→提交→普通 PR 核对→暂停继续”，为真实 GitHub 适配提供可重复检查的运行骨架。

**Architecture:** 扩展协调器是会话唯一写者；页面代理按需采集与高亮，React 侧栏只消费已提交快照。首轮 fixture 适配器与真实 GitHub 适配器使用同一通用接口、不同能力 ID；Fastify 先提供独立健康入口，模型随后接入。

**Tech Stack:** TypeScript、React、WXT、npm workspaces、Fastify、Driver.js、Ajv 2020 standalone、Vitest、Playwright。Node 24 LTS／npm 11；补丁版本与包组合依[工程配置](WebGuideAI-工程配置与开发方式-v0.1.md#2-版本与依赖)在首次安装时核查并锁定，不覆盖个人全局环境。

**Spec:** [协作适配契约](GitHub协作适配契约-v0.1.md)、[通用运行契约](WebGuideAI-运行契约-v0.1.md)、[SC02 规格](../requirements/GitHub协作首场景规格-v0.1.md)。取代 [11 月 17 日旧计划](首轮工程实施计划-2026-11-17.md)的执行地位。本计划只交付运行基础，真实网站、模型和完整 SC02 验收在后续切片完成。

## 本轮实现深度（11 月 18 日评审修订）

目标是先得到可操作的模拟闭环，各机制按下列最小实现落地，不为未来场景提前搭框架。

| 范围 | 本轮落实 | 后续再做 |
| --- | --- | --- |
| 状态与停止 | 单写者、上下文身份、拒绝旧结果；STOP／ACK 按已绑定文档记录待确认集合 | 多 owner 并发、跨设备恢复及通用分布式协调 |
| 页面失联 | 一份本页租期计时器；仅当前授权可续期，失联／过期立即 clear 并停采集 | 自适应心跳、重试调度和批量租期管理；保留 6,000／2,000 ms 初始值 |
| 容量 | 清理已过期／明确失效且不用于当前结论的历史，仍超限则拒收并暂停 | 按优先级裁剪、压缩、后台归档；不实现 LRU 或配额自调算法 |
| 教程格式 | 从现有 v1／v2 Schema 构建生成校验器，顺序显示 12 步 | Schema 共用定义重构、stageId 与折叠分组 |
| 集成检查 | 单元检查覆盖规则反例，浏览器检查一条主线及关键交互回归 | 真实 GitHub 页面与 Edge 原生侧栏、模型和完整支持矩阵 |

Ajv standalone 保留，直接在构建时生成两份校验器，不另建 Schema 生成平台；[官方说明](https://ajv.js.org/standalone.html)支持这一使用方式。页面租期和身份校验保护的也是模拟闭环中的暂停与旧结果，不等接入真实 GitHub 后才补。

本机预检已用并行安装的 Node 24.22.3／npm 11.19.1 跑通既有检查，配套 Chromium 已能加载既有 MV3 实验。具体环境、测试边界与小组接入见[工程配置第 9 节](WebGuideAI-工程配置与开发方式-v0.1.md#9-开工前检查与小组接入)。任务 1 使用该可用基线核对正式依赖兼容、安装和构建。

## 真实 GitHub 源码短验证

状态：待执行。工程恢复后，从任务 1 起步，在任务 3 的模拟采集与任务 5 的页面接线前安排一次短验证；任务 1、2 可照常推进。

1. 使用获准练习仓库中一份已知原文的 UTF-8 Markdown。选用含空行、中文和末尾换行的文件，记录完整提交 SHA 和仓库内路径。
2. 打开同一 SHA 和路径的不可变文件页，在用户可见的 Code 视图核对对象身份与完整文本。对照已知原文检查空行、Unicode、末尾换行及完整长度；只按协作契约把 CRLF 规范为 LF。记录 Preview、折叠行、截断和行号是否会干扰读取。
3. 记录环境、读取方式、SHA／路径来源、比对结果及缺项。完整性可证时记为该读取路径可行；任一部分无法证实则记为待确认，提出具体补证路径。短验证结果用于后续真实适配设计，模拟工程按计划继续。

## Global Constraints

- 同时活动引导 1 个 owner，同会话最多 5 个任务；每任务最多 100 条观察，快照总量软上限 1 MiB。只清理已过期／明确失效且不用于当前结论的历史；仍超限则拒绝新增、暂停活动引导并提示清理，停止命令不被容量检查拒绝。
- 消息 64 KiB；证据有效期 5 分钟；本地采集超时 3,000 ms；页面租期 6,000 ms、续期 2,000 ms。
- 核对 epoch、任务、目标修订、教程身份、上下文、绑定、浏览器发送端文档及检查顺序；后台重启活动任务转 paused/recovery-required。
- 网站操作由用户执行；输入／点击／提示条不证明保存或 PR 交付；未知、过期、读失败不沿用旧成功。
- v1／v2 分别校验；v2 才允许 input；未注册运行能力拒绝启动。构建时生成校验器，不在扩展运行时动态编译。
- 模拟任务使用 fixture_collaboration_v1，生产入口禁用；不导入 experiments 或 research/repos 源码，不自动启动个人浏览器。
- 首轮产品代码只读取模拟页，模型请求和反馈留到后续；界面明确“开发模拟”。真实源码短验证独立记录。
- 沿用已有 Git 仓库及由文档 PR #3 交付的基线。实施时使用独立 codex/ 分支及隔离检出，保存当前修改，不重复初始化；工程 PR 按协作约定单独验收。

## Review Focus

1. v1 教程被误当 v2、未知字段／引用混入：加载拒绝，不降级猜测——任务 1。
2. 未保存文本、旧标记、Draft 或额外文件触发成功：逐项反例，终验保持未通过——任务 3。
3. 旧文档、旧 owner、旧 STOP／结果写入新会话：身份与时序核对，暂停不丢失——任务 2、5。
4. DOM 重建、多匹配、提示含 HTML：先撤高亮、唯一定位、按纯文本渲染——任务 5。
5. 快照保存失败／超限、正文超限或读取不完整：停止新指示，显示明确缺项——任务 2、3。

## 文件与接口边界

| 位置 | 职责 |
| --- | --- |
| packages/contracts/src/ | 公共类型、v1/v2 格式与引用校验、消息边界 |
| apps/extension/src/runtime/ | 单写者协调器、证据筛选、检查点及停止记录 |
| apps/extension/src/adapters/fixture-collaboration/ | 模拟页面定位／采集与纯校验器；以后 GitHub 适配器作为同级目录 |
| apps/extension/src/browser/、page/、sidepanel/ | 浏览器身份与授权、局部 DOM 与渲染、侧栏 |
| apps/api/src/ | 独立应用工厂与健康接口（任务 4） |

| scripts/ | 生成校验器、检查构建与能力隔离 |

公共类型名：TutorialVersion、TutorialIdentity、Capabilities、TaskTarget、SessionCheckpoint、RuntimeEvent、TrustedSender、Effect、EvaluationInput、Decision、LocationResult。字段以两个契约为准。`TaskTarget` 按 profile 区分 PagesTarget、CollaborationTarget 和 FixtureCollaborationTarget；本轮只注册 fixture 的运行实现。

`FixtureCollaborationTarget` 使用 CollaborationTarget 的业务字段，profile 改为 fixture_collaboration_v1，并增加受控 origins 列表（仅 http://127.0.0.1:43131 与 :43132）。生产 GitHub 目标不接受这个字段。fixture 教程 ID 为 fixture.collaboration.first-pr，12 步与协作样例对应，所有 collab. 能力引用改为 fixture.；文件独立保存，不能修改设计样例后冒充原内容 hash。

默认模拟任务为 repo=fixture-team/guide、Issue #1、member=fixture-user、base=main、head=practice/first-pr-001、path=docs/practice/first-pr.md。文件初始内容为“待补充：我的协作说明。”加末尾 LF；before 为该句，after 为“已完成协作练习 WG-FIXTURE-001。”，practiceMarker=WG-FIXTURE-001。新任务生成新 marker；负例工厂不得沿用上次任务的通过观察。
