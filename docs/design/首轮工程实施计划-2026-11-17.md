# WebGuide AI 首轮工程实施计划

**执行前更新（2026-11-17）：**发起人已将首场景调整为 [GitHub 小组协作入门](../requirements/首场景调整-GitHub协作-2026-11-17.md)。本计划仍保留原技术切片供修订参考，当前不作为可直接执行的新首版计划。须先完成 SC02 路径与验收，并核对教程 Schema、输入动作、任务身份和校验器的适配，再修订实施任务；原 Pages 下一切片安排已不代表当前优先级。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 默认由当前助手在本会话逐项实现；本计划不安排并行修改核心文件。

**Goal:** 建立正式工程，并在自有页面完成“加载教程→选择与保存→规则检查→页面高亮→暂停恢复”的可重复运行闭环。

**Architecture:** 扩展内的协调器是会话唯一写者，页面代理采集和渲染，React 侧栏消费已提交快照。共享包负责教程与消息契约，Fastify 先提供独立健康入口。演示教程只在开发／测试构建启用，完整 Pages 适配在下一切片接入。

**Tech Stack:** Node 24.22.3、npm 11 workspaces、TypeScript、React、WXT、Fastify、Driver.js、Ajv 2020 standalone、Vitest、Playwright；精确依赖经首次安装核对并锁定。

**Spec:** [工程配置](WebGuideAI-工程配置与开发方式-v0.1.md)、[引导交互](WebGuideAI-引导交互-v0.1.md)、[运行契约](WebGuideAI-运行契约-v0.1.md)及[教程 Schema](contracts/tutorial.schema.json)。本文为待实施计划，勾选项不是已完成记录。

## Global Constraints

- 同时活动引导：1 个 owner；同会话保留任务：最多 5 个，含活动任务。
- 每任务观察记录：最多 100 条；快照总量软上限 1 MiB；当前证据不被挤出。
- 单条协议消息：64 KiB；观察有效期：5 分钟；本地采集请求超时：3,000 ms。
- 页面活动租期／续期：6,000 ms／2,000 ms；后台重启活动任务恢复为 paused/recovery-required。
- 消息核对 epoch、任务、目标、步骤上下文、绑定、浏览器发送端文档及检查顺序；旧响应不推进。
- 页面操作由用户执行；点击不等于成功；未知、读失败、过期不沿用旧成功。
- Node 基线不通过全局覆盖安装实现；构建不自动打开个人浏览器，不导入 experiments 或 research/repos。
- 模型接口、反馈提交和真实 Pages 验证不在本切片实现；界面必须明确开发演示和实际未提供的能力。

## Review Focus

1. 非法／不受支持的教程：未知字段、重复 ID、缺失来源及未注册能力拒绝启动——任务 1。
2. 错误标签、文档或上一轮请求：不能借相同 URL／stepId 写入当前观察——任务 2、4。
3. 暂停、关闭连接与后台恢复：旧回复或旧 STOP 不推进／误停新会话——任务 2、4。
4. 目标被替换、多候选或网页输入含特殊字符：撤销旧指示，提示按纯文本显示，真实控件可用——任务 4。
5. 快照保存失败或容量不足：不发布新的可操作指示，不伪造成功——任务 2。

首轮开发教程 ID 为 fixture.choose-save，适配器／参数 profile／终验器均为 fixture_v1，仅在开发／测试注册。目标为 {profile:"fixture_v1",targetRevision:1,url:"http://127.0.0.1:43131/guide.html",expectedBranch:"main"}。Pages 的参数格式不因此改变；通用会话使用按 profile 区分的 TaskTarget 类型。

模拟页有 select#branch、button#save、p#saved-status：分支最初为 none；选择 main 后 Save 可操作；点击后先显示“保存中”，完成后显示“配置已保存：main”。两步 ID 为 choose-branch／save-configuration，标题为“选择目标分支”／“确认配置已保存”；分别检查 value-equals main、text-equals 配置已保存：main（第二步 check.target 指向状态，而高亮 target 为 Save）。fixture 终验器要求两步当前证据均满足；结果展示“开发演示已验证”，不能写“GitHub Pages 已发布”。页面由正式测试目录新建，可借鉴旧实验机制，不复制旧 taskId、固定仓库或实验租期。

所有以下路径均相对当前工作区根。执行时如尚无本地 Git 仓库，按工程配置先检查可提交范围、初始化并记录起点；不创建远程、不推送。每个任务完成后只提交该任务文件和相应记录；Git 元数据不可写时保留工作及检查结果，不为提交而修改权限配置。

**Interfaces:**

- Produces: `loadTutorial(jsonText: string, capabilities: Capabilities): Promise<TutorialLoadResult>`，结果为 `{ok:true,tutorial,identity}` 或 `{ok:false,code,issues}`；identity 含 SHA-256 contentHash，issues 含字段路径，不抛出未处理解析异常。
- Produces: `parseEnvelope(raw: unknown): EnvelopeResult`，结果为 `{ok:true,envelope}` 或 `{ok:false,code,issues}`；核对公共信封及消息大小。浏览器发送端身份由后续适配层提供，不因格式通过而信任 payload。
- Produces: TutorialVersion、TutorialIdentity、TaskTarget、SessionCheckpoint、RuntimeEvent、TrustedSender、Effect 的类型，业务字段沿用运行契约；FixtureTarget 为首个目标 profile，Pages 类型保留其既有字段。
- Produces: `makeTutorialText(patch?: Partial<TutorialVersion>): string` 测试工厂；能力表区分“格式中出现的能力描述”与“本构建确有实现的能力”。fixture 运行注册不能顺带启用 Pages。

expect(await loadTutorial('{', fixtureCapabilities)).toMatchObject({ok:false, code:'INVALID_JSON'});
expect(await loadTutorial(withDuplicateStepIds, fixtureCapabilities)).toMatchObject({ok:false, code:'DUPLICATE_STEP_ID'});
expect(await loadTutorial(withUnknownSource, fixtureCapabilities)).toMatchObject({ok:false, code:'UNKNOWN_SOURCE'});

- [ ] **2. 运行失败检查。** `npm exec vitest run packages/contracts/tests`；应因缺少实现／生成校验器失败，不能把安装失败当作需求失败。

## 任务 2：可停止、可恢复的单写者协调器

**Files:**

- Create: apps/extension/package.json（本任务所需的模块／测试配置，任务 4 再补 WXT 应用构建依赖）。
- Create: apps/extension/src/runtime/{coordinator.ts,evidence.ts,fixture-verifier.ts,limits.ts}。
- Create: apps/extension/src/runtime/__tests__/{coordinator.test.ts,evidence.test.ts,helpers.ts}。
- Create: apps/extension/src/browser/session-store.ts、apps/extension/src/browser/__tests__/session-store.test.ts。

**Interfaces:**

- Consumes: 任务 1 的类型及已加载教程；不接收任意 JS checker。
- Produces: `createCoordinator(deps: CoordinatorDeps): Coordinator`，公开 `handle(event: RuntimeEvent, sender: TrustedSender): Promise<CommandResult>` 与 `recover(): Promise<void>`。
- CoordinatorDeps 为 store、clock（`now():number`）、makeId、emit（`effect:Effect → void`）、publish（`snapshot:SessionCheckpoint → void`）；clock 使用依赖注入，不直接绑真实时钟。
- Store 为 `readAll():Promise<SessionCheckpoint[]>`、`write(snapshot):Promise<void>`、`remove(taskId):Promise<void>`；`createSessionStore(sessionStorage: SessionStoragePort): Store` 注入 get／set／remove 端口，任务 4 才传入真实 browser.storage.session。读写异常向上返回，任务 2 测试无需 WXT 全局。
- Effect 包括 CheckRequest、ShowGuide、Stop、CancelRequest；均带运行契约身份。emit 只派发，不在事件队列里等待页面响应。
- CommandResult 为 accepted／conflict／rejected 及可返回的已提交快照；消息去重仅限当前 coordinatorEpoch。
- 首轮入口事件为 USER_START／USER_CONTINUE／USER_BACK／USER_ADVANCE／USER_RECHECK／USER_PAUSE／EXIT；内部事件为 UI_LOST／CHECK_RESULT／LOCATION_INVALIDATED／REQUEST_TIMEOUT。USER_START 只携带 tutorialId／version／target，由协调器取本构建注册内容，不能信任 UI 传任意教程或已完成状态。

- [ ] **1. 写协调器失败测试。** helpers 提供可信窗口／文档 sender、假时钟、可失败的 memoryStore 和已加载 fixture 教程，至少固定：

```ts
expect(afterUnselectedBranch.state).toBe('guiding');
expect(afterPauseAndLatePass.state).toBe('paused');
expect(afterReviewOfPassedStep.navigationIntent).toBe('review');
expect(afterReviewOfPassedStep.displayStepId).toBe('choose-branch');
expect(afterRefreshReadError.currentEvidenceIds).not.toContain(oldSuccessId);
expect(effectsAfterStoreFailure.some(e => e.type === 'SHOW_GUIDE')).toBe(false);
```

其中 currentEvidenceIds 为测试辅助函数计算的当前集合，不新增同名持久字段。另固定错误文档、旧 epoch／sequence、旧 owner 断开、过期证据和重复消息的预期。
- [ ] **2. 确认失败。** `npm exec vitest run apps/extension/src/runtime`；应因协调器／证据处理未实现失败。
- [ ] **3. 实现协调器与 fixture 校验。** 逐任务短事件串行、提交成功后 emit；actionable 与 guiding 衔接；review 不自动推进；单活动 owner；重查立即使同范围旧观察退出判定；最终守卫不接受 AI 或单纯点击。按工程配置实施容量、超时、租期和停止记录，未知恢复不推断成功。
- [ ] **4. 通过边界检查。** 同上测试命令及 `npm exec vitest run apps/extension/src/browser/__tests__/session-store.test.ts`。假时钟覆盖 3,000 ms 本地超时、5 分钟过期；恢复生成新 epoch、活动转暂停；满 5 任务拒绝静默新建；100 条历史只裁剪失效项；超过 1 MiB 或真实 store 拒绝不发布新指示。旧 STOP／ACK 不改新上下文，停止意图不因 UI revision 落后被拒绝。
- [ ] **5. 记录并提交。** 保留行为检查结果，不写“真实 Edge 生命周期已通过”；按任务文件清单提交。
