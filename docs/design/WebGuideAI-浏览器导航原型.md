# WebGuide AI 浏览器导航原型

更新于 2026-11-20。本页是当前原型的需求、设计和验收入口。实时导航从 `main` 切出独立分支，按需要复用元素定位、页面观察和高亮。固定路线与 GitHub 文件核对保存在 `codex/github-raw-source`，首轮协作练习可从原提交查阅。新扩展的入口和构建以实时导航为准。[开发顺序](../requirements/版本交付范围-2026-11-17.md#当前开发顺序)

## 原型希望用户看到什么

用户打开扩展，说「带我找到这个仓库 README 的编辑入口」。AI 看当前页面，决定该高亮哪个链接、菜单或按钮，以及旁边该提示什么。扩展在网页上显示高亮和气泡，用户自己操作。用户可以从已经打开的 README 开始，也可以在途中自行切换页面，AI 根据眼前的状态重新判断。

例如用户点了编辑按钮后，GitHub 显示 Fork 提示。如果用户只想知道编辑入口在哪，扩展可以说明入口已找到，并解释 GitHub 为什么要求 Fork。如果用户想继续进入编辑器，AI 根据页面说明可选路径，由用户决定是否继续。扩展根据当前页面区分已经看到编辑区和还差一步。

## 为什么叫浏览器导航 harness

这里的 harness 是**给 AI 提供网页观察、视觉指引和结果反馈的运行层**。浏览器扩展是它接触网页和用户的地方。模型根据页面选下一步并写提示，扩展把选择变成实际高亮和气泡。用户操作后，扩展把新页面状态交回给模型。换一个站点，按钮和页面会变，观察、定位、高亮和回读这套机制还能接着用。

| 部分 | 在原型里负责什么 |
| --- | --- |
| 浏览器扩展 | 从当前标签页提取标题、可见按钮和链接、所属区域等有用信息，用临时编号表示控件。按 AI 的建议渲染高亮和气泡，观察用户操作后的页面。 |
| AI | 结合用户目标、眼前的控件、上一步结果和相关经验，决定高亮目标和提示。页面跳转后可以调整指引，缺关键条件时可以解释或向用户提问。 |
| 经验库 | 保存一小段可以复用的做法，比如「在文件工具栏找 Edit 入口」，以及它适用的情境、实际结果和来源。 |

先用网页自身的结构来定位。遇到图标名称缺失、页面布局无法从结构理解的场景，再试截图。第一版沿用现有扩展和后端，打通「读页面 → AI 选控件和提示 → 扩展高亮 → 用户操作 → 读结果」这一轮即可。

### 一次引导怎么往下走

1. AI 返回「高亮控件 7，提示『点这里打开文件操作菜单』」。扩展确认控件还在当前页面，然后显示高亮和气泡。
2. 用户自行点击、滚动或切换页面。扩展等页面有实质变化时再观察。目标与页面都相同时，保留当前高亮。
3. AI 根据新状态指下一步。页面已跳转时，过期的控件编号随旧页面失效。到达目标时显示结果，遇到权限提示就解释当前卡点。有多个相似控件、无法确认目标时，先在侧栏提问或请用户选路线。

AI 从第一个提示就参与选路，可以根据用户自己选择的入口接着引导。原型先检验网页高亮和提示能否跟上真实操作。

## AI 怎么把一次引导变成经验

先用一份本地经验表跑通闭环。扩展观察到预期结果后，让 AI 从这段引导里提取候选经验并存到本地。比如下面这条。

| 要记什么 | README 例子 |
| --- | --- |
| 适用情境 | GitHub 仓库内已经打开目标 README，目标是进入该文件的编辑器。 |
| 可尝试的动作 | 在文件工具栏找编辑入口。编辑图标可能单独显示，也可能藏在菜单里。 |
| 结果与例外 | 出现该 README 的编辑区才算进入编辑器。出现 Fork 提示时，记录权限分支及对应提示。 |
| 来源 | 实际引导时看到的页面状态，以及用户操作后出现的结果。 |

下一次，先把相关经验交给 AI，让它结合当前页面决定能否用上。成功复现、判断条件也简单的片段，可以让扩展直接匹配并高亮。遇到页面改版或经验不符，就继续实时找路，回头更新那条经验。失败记录也可以简短保留，帮助识别来回跳同一页面等卡点。官方文档和人的示范都可以作为经验来源，完整固定教程仍然适合需要统一演练的任务。

这轮先回答一个具体问题：**一次引导学到的做法，在另一个起点或另一项相似任务里能不能复用？** 一次成功只是线索。后续复现时看能否减少步骤或模型调用，以及页面稍有变化时能否继续指对。

## 第一轮怎么验证

| 验证项 | 做法 | 记录什么 |
| --- | --- | --- |
| 实时指路 | 在 GitHub 找 README 编辑入口、打开指定 Issue，从仓库首页、文件页或其他中间页开始。 | 首次高亮是否正确，是否到达目标页面，哪一步选错。 |
| 页面变化后换路 | 在模拟页改动菜单层级或加入 Fork 提示，让用户自己点击。观察 AI 能否根据变化重新高亮或给出提示。真实 GitHub 上核对有写权限和无写权限时看到的不同状态。 | 是否能继续指路，是否识别权限分支，是否正确报告到达或卡住。 |
| 模型不可用或高亮建议失效 | 模拟模型不可用、页面已跳转或建议的控件已经消失。 | 侧栏说明暂时无法继续，用户可以重试。过期高亮及时清除。 |
| 换站点 | 用同一套页面观察和视觉引导能力，在第二个真实站点从一个打开菜单或进入指定页面的任务开始。 | 哪些部分直接复用，哪些地方仍需站点特有知识。 |
| 复用经验 | 在相同起点比较有经验和无经验的实时引导，再用一个相似起点看经验能否迁移。需要固定路线作对照时，单独运行旧版。 | 对比到达结果、误指次数、模型调用次数和等待时间。 |

首轮以跑通以上闭环并留下几条可复现记录为完成标志。实验之后再决定经验库能承担多少内容，以及是否需要作者工具。
