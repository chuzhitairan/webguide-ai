# 导航 Harness 首轮实施计划

> 本轮按可独立验证的模块实现，再从生产扩展入口联调。用测试先复现缺少的行为。

**目标**　从自然语言目标出发，用同一套观察和补看流程高亮真实网页控件，等用户操作，再确认结果。

**结构**　扩展侧栏负责会话和模型请求，网页脚本负责观察和绘制。本机服务接收这一轮的证据，向已配置的模型请求一项决定。两端共享一份协议。

**设计依据**　[导航 Harness 设计](WebGuideAI-导航-Harness-设计.md)

| 模块 | 文件与职责 | 验证 |
| --- | --- | --- |
| 模型服务 | `apps/api/src/guide-protocol.ts` 定义共享数据和回复校验，`guide.ts` 管理单次模型判断，`app.ts` 提供带扩展来源和令牌校验的本机路由 | 合法目标能获得指引，未授权请求不会进入模型，超时或格式错误可识别 |
| 页面观察 | `apps/extension/src/page/snapshot.ts` 生成带编号的首读、局部补看和结果证据，复用现有定位与绘制 | 首读范围外的控件可补看，隐藏或复用的目标会失效，屏外记录与实际可点击状态分开 |
| 引导循环 | `apps/extension/src/guide/session.ts` 调度补看、复核、下一步和完成，`entrypoints/guide-page.ts` 接收网页指令 | 批量补看只走一次回包，用户操作前不替用户点击，过期回复不会应用，结果生效才完成 |
| 扩展入口 | `entrypoints/background.ts` 记录工具栏授权，`src/sidepanel` 提供自然语言输入和状态，浏览器桥接绑定当前标签页和文档 | Playwright 加载生产扩展，在本机模拟页面上从补看走到完成，核对跳转清理 |

同济模型沿用本机配置。首轮以模拟模型验证调用与页面闭环；随后安排两站真实模型验证，再决定视觉和经验试验的工作量。保留现有 TypeScript、WXT、Fastify 和 Driver.js 依赖。
