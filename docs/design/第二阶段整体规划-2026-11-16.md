- 暂按每周 12–15 小时有效推进粗排，本阶段约 23–35 小时、2–3 个工作周。实际投入尚未确认，前两个工作包完成后校准，不承诺固定完成日期；招募、等待反馈与额外课程材料时间另计。

## 5. 重点风险怎样验证

| 风险 | 最小验证场景 | 要回答的问题／处理方式 |
| --- | --- | --- |
| 权限与跨源导航 | 从 GitHub 设置到工作流，再到实际目标站点，包含同源刷新、新标签页和跨源；分别检查有权限、未授权和撤销权限 | 分别记录授权、注入与任务状态。比较目标主机可选授权及脚本注册方案，不能假定 activeTab 刷新就失效，也不能假定它自动覆盖跨源 |
| 高亮不可靠 | 目标唯一、多个同名目标、目标消失、滚动、窗口变化和页面重建 | 高亮始终对应实际目标；不唯一或不存在时显示可理解的提示，不沿用旧坐标。核对选用组件在扩展内的实际效果 |
| 剧本仅是硬编码搬家 | 同一运行机制处理两份控件不同的本地样例及参数变化；对 Pages 样例校验输入 | 步骤顺序和参数可由剧本改变，通用运行机制不依赖固定仓库；站点提取放在适配器。不为此扩展到新的正式网站场景 |
| 完成证据误关联 | 不同仓库、其他提交／run、站点旧内容、过期观察与读取失败 | 能拒绝误报完成，并说明缺什么；定义目标提交和预期内容如何绑定，无法判断时保持待确认 |
| 状态恢复错误 | 关闭引导、刷新、后台进程重启、暂停期间页面变化，以及旧消息晚到 | 目标与会话隔离；恢复后重新核对，旧观察／响应不能推进新页面或已结束的任务。浏览器重启后提示重新开始 |
| AI 越界或不可用 | 用契约样例模拟无依据回答、页面指令干扰、超时、失败和过期返回 | 模型结果不覆盖规则状态；固定引导继续可用；只传必要上下文。模拟结果证明接口处理，不代表真实模型效果；有可用模型配置后再补真实问答验证 |

独立自动化优先使用受控样例和独立测试配置，不接管个人浏览器。若运行通道暂不可用，保留用户代操作与截图的方法，明确自动化覆盖缺口，优先定位影响当前任务的阻塞。

## 7. 控制文档数量

计划中的主要产物集中为四组，具体路径在设计和建仓时落定：

1. SRS 与一张需求—设计—验证追溯表，基于现有草案整理。
2. 一份核心设计文档，内含架构、模块职责、状态／通信图、权限生命周期、异常、选型和验证结论。
3. 契约与模型源文件：v1/v2 剧本 Schema、协作示例与兼容的 Pages 示例、接口定义及必要图形源码。
4. 正式工程骨架、启动说明、测试／CI 和下一阶段实现计划。

风险与试用结果回写对应设计节，不为每次讨论重复创建长报告。代码级实施计划在核心设计审阅后细化到文件、接口、任务和验证命令。
